## 二、已修（2 处）

### P1 · 应用整个渲染不出来（阻断级）

**现象**
窗口空白，e2e 连 `.hb-shell` 都等不到。探针（Chromium 直载 `dist/`）拿到真实栈：

```
ReferenceError: islandDotState is not defined
    at renderTrigger
```

**根因**

`frontend/app/src/shell/AppShell.jsx` 顶栏「灵岛」按钮块：

```jsx
<span className="hb-island-dot" data-state={islandDotState} />
<span>{islandText}</span>
```

- `islandDotState`、`islandText` **全仓只此一处出现，从未声明**；
- `data-state` 在 `AppShell.css` 里**没有任何选择器**（CSS 认的是 `[data-busy="true"]`）；
- 同时丢掉了原有的标题与副状态。

⇒ 首渲染即抛错，整个外壳挂不上。

**改动**

恢复为 r28 覆盖前的写法（与 CSS、与 e2e 的模型名断言一致）：

```jsx
<span className="hb-island-dot" data-busy={String(busy)} />
<strong>{topTitle}</strong>
<span>· {topSubStatus}</span>
```

**验证**：探针 `shell=true`（修复前 false）；e2e 恢复推进。

> 与 r13 的 `activeModel` TDZ 同类：**构建绿、单测绿、铁律绿，应用却一行都渲染不出来**。
> 这类问题只有"真的渲染一次"才能发现。

### P2 · 沙盒「抓起即松手」被误判为吸附归位

**现象**：`unit 56` 失败 —— `releaseGlassBody(...).snapped` 期望 `false`，实际 `true`。

**根因**（`src/platform/glassSandboxEngine.js`）

```js
if (distHome < 56 && speed < 320 && b.biteNotches.length === 0) { /* 吸附归位 */ }
```

松开瞬间位移为 0 ⇒ `distHome = 0` 恒成立，**"抓起来没动就松手"也被判成"拖回原位"**。

**但两侧意图都要成立**：

- r28 规格：**慢滑不归位**，只有长按召回才回原位；
- 界面需要：**拖回原位槽 → 磁吸归位**（`GlassSandboxOverlay.jsx:130` 用 `res.snapped` 还原真按钮）。

**改动**：抓取时记录 `grabPos`，吸附额外要求**真的移动过 ≥ 8px**：

```js
const movedFromGrab = b.grabPos ? Math.hypot(b.x - b.grabPos.x, b.y - b.grabPos.y) : Infinity
if (distHome < 56 && speed < 320 && movedFromGrab >= 8 && b.biteNotches.length === 0) { ... }
```

**验证**：`unit 57/57`（含该条）。

## 三、未修（3 处）

### P3 · 3D 助手浮层压住底部操作条（按你的要求不动助手）

**现象**：e2e 里 `locator` **找到了**按钮，但点击被拦截：

```
<div class="cp-actor" data-companion-actor="true" …> intercepts pointer events
```

- 受影响的按钮：群聊「发起接力」、工作流「中止执行」（可能还有别的底部条）；
- 机制：`.cp-actor { pointer-events: auto }` + 默认落点 `x=vw-160, y=vh-168`（右下角），层级 `--z-companion: 175`；
- `.hb-main` 有 `will-change: transform` 会形成层叠上下文，**子元素抬 z-index 也压不过它**。

**处置**：**产品代码未改**（按要求）。测试侧等价处理 —— 开局隐藏助手（等同于你把它挪开），Suite T 之前写回 `visible:true` 并重载页面。

> 我曾试过把默认落点上移 132px，**已撤回**。

### P4 · Suite T：捏脸工坊点了不出现（未查明）

**现象**：`e2e` 中右键助手 → 点「🎨 3D 捏脸与换装工坊」→ 等
`[data-section="companion-customizer"]` 超时。

**已排除**：

- 菜单项存在：`CompanionOverlay.jsx:458`（`cp-ctx-item`，文案 `🎨 3D 捏脸与换装工坊`）；
- 自定义器根属性存在：`CompanionCustomizer.jsx:36` 带 `data-section="companion-customizer"`；
- 打开逻辑存在：`setCustomizer({ open: true, tab: 'avatar' })`，渲染条件 `open={customizer.open}`。

⇒ **文案与选择器都不是原因**，点击到打开之间断了，具体断点未定位。
按"不动助手"的要求，**没有继续改它的实现**。

**下一步可选**：加一次临时探针（记录 `customizer.open` 变化）定位断点；或由交付方自查。

### P5 · 「工具箱唤回助手」的承诺不存在

隐藏助手后的 toast 写：

> 已暂时隐藏 3D 助手，可在顶栏「工具箱」随时唤回

但全仓只有这一句 toast 提到「唤回」，`visible: true` 仅由 `CompanionOverlay.jsx:81` 内部设置，
**顶栏没有唤回入口** ⇒ 用户一旦隐藏，界面内无法恢复（只能改 localStorage）。
属**文案承诺了不存在的功能**，未改动（涉及助手，按要求不动）。

### P6 · 设置保存的接口放大器（跨轮遗留）

`state/settingsSlice.js` 每个保存函数末尾都调 `refreshSettingsAux()`，
而它（`state/domainSlice.js:211`）一次并发拉 **9 个配置接口**。
实测：会话里配置接口各被调用 **11 次**（≈ 11 次保存 × 9）。

**未修原因**：属产品行为决策（合并刷新 / 防抖），未获授权不动语义。
**建议**：200ms 防抖合并（不改语义、改动小）。
