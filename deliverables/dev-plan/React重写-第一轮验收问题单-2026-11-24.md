## 二、五条问题（按用户原序）

### 1. 模型无法调用（阻断级）

**证据**：`01-屏幕截图 2026-11-24 114936.png`
界面上是红框报错：

```
请求/执行错误：模型请求失败：Failed to fetch
```

**现象定性**：`Failed to fetch` 是 `fetch()` 在网络层就失败——**请求根本没拿到响应**。
它不是 4xx/5xx（那会有状态码），也不是上一轮修的 `ISO-8859-1`（那个在发请求前就抛、文案不同）。

**可能的三类原因**（待查，本轮不下结论）：

| 类别 | 判据 |
|---|---|
| 本地代理未就绪 | 日志里 `get_local_proxy` 返回 200，但代理端口是否真的在监听未验 |
| 协议/CSP 拦截 | 新前端从 `harbor://app/` 加载，请求若直连 `http://127.0.0.1:<port>` 可能被协议策略拒 |
| Base URL 空/错 | 新 `services/modelTransport.js` 是否读到了旧配置键（配置键名与旧前端不同） |

**下一轮第一步**：在渲染进程里打印 `request.endpoint` 的实际值 + 用 `curl` 直连同一 URL，
两者一比就能定性是"配置错"还是"被拦"。**不要先改代码**。

### 2. 左侧边栏「太土」（用户一字评价）

**证据**：`02-屏幕截图 2026-11-24 114932.png`

**注意这不是审美问题，是布局塌陷**：截图里每一项都是**竖排单字**
（历 / 空 / 计 / 群 / 协 / 析 / 市 / 搜 / 副 / 设……），说明侧栏宽度不足以容纳文字，
每个汉字被挤成一行。观感"土"是结果，根因是宽度/写法（纵向标签或宽度坍缩）。

**建议方向**（下一轮再定）：图标 + 横排文字，或纯图标 + 悬浮标签；侧栏最小宽度要能容纳 4 个汉字。

### 3. 顶部菜单毫无作用，去掉

**证据**：`03-屏幕截图 2026-11-24 114922.png`（File / Edit / View / Window）

这是 **Electron 默认应用菜单**，桌面应用里没有实际用途。
`electron/main.js` 里既没有 `Menu.setApplicationMenu(...)` 也没有禁用——
即"没关过，所以是默认那套"。

**修法（下一轮）**：`Menu.setApplicationMenu(null)`（macOS 需保留最小 appMenu，Windows 直接置空）。

### 4. 图标太丑，重新设计

**证据**：`03-屏幕截图 2026-11-24 114922.png` 左上角图标

现在是一团细密的多环线条，缩小到 16–20px 时**辨识度几乎为零**，看不出是什么。

**建议方向**：单一强轮廓的主形态（字母标或极简几何），保证 16px 下可辨；
多环/细线在小尺寸必然糊成一团。

### 5. 透色太暗

**证据**：三张图整体偏暗（尤其中部区域）。

**现象**：透色链路对，但整体明度低。可能叠加了三个因素：

1. 三阶玻璃 alpha 偏高（侧栏 0.52 / 舞台 0.68 / 卡片 0.84）——暗色壁纸下会把整体压暗；
2. 应用底色本身是深色档（`rgb(20,19,18)` 级别的底），亚克力再叠一层就浮不起来；
3. 亚克力自身带的 tint（Windows 会给材质加系统色）。

**建议方向**：优先提"底色 + 舞台阶"两处，别一次改三阶；改完在同一张壁纸下对比截图。
