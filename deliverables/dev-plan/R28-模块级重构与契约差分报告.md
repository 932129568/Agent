## 2. 拆分方案（为什么这样拆）

大模块内部函数往往相互调用，若随意按行切半会产生**双向依赖**，而 `frontend/build.js` 的 lint 要求 `requires` 必须在此模块之前已提供。因此采用：

1. **只抽「纯常量表 / 状态变量 / 零依赖纯函数」**——被抽组不调用留在原文件的函数，依赖严格单向（原模块 → 新模块）；
2. **新模块插在原模块紧前面**，原模块 `provides` 删去迁移符号、`requires` 追加迁移符号；
3. **精确行搬移**：新文件只承接原文件的既有行，**不新增、不改写、不删除任何一行**；原文件保留剩余行。这样「所有 `frontend/src/**/*.js` 非空行的多重集」恒定，可作为「代码零改写」的硬证据；
4. 不新增顶层符号、不新增 DOM id / onclick / callApi 目标、不改任何函数体。

## 9. 回归定位与测试基础设施适配（如实记录）

### 9.1 现象与根因

首轮全量 46 项失败集中在 `test_connect_merge.py`、`test_freetoken_preset.py`、`test_nemotron_preset.py`、`test_v16_batch*`、`test_round6/7_adversarial.py`、`test_session_project_redesign.py`、`test_sidebar_run_status.py`、`test_review_fixes.py`、`test_v18_search_service.py` 等 13 个文件，典型报错 `AssertionError: 未找到函数 streamSpeedText`。

**根因**：这些 vm 沙箱测试通过 `helpers/frontend.py` 的 `read_frontend_source` / `frontend_node_map`，按**单个模块文件**（旧名如 `36-connect.js`、`60-agent-loop.js`、`63-search-panel.js`、`85-session-mgmt.js`）加载源码并在隔离 vm 里执行。拆分后原本同处一文件的常量/函数分散到两个文件，单文件加载不再完整。

**重要教训**：§4 的独立契约差分证明了「顶层符号集合 / UI 契约 / API 契约 / 构建产物契约面 / 源码行多重集」零漂移，但**契约面 ≠ 测试加载契约**。模块级重构除对外契约外，还必须把「测试 harness 如何装载模块」纳入差分/适配范围。这是首轮门禁失败的唯一原因，产品代码本身零回归。
