## 一、四条问题

### 1. 群聊接力：无法自定义角色与角色模型，无法暂停（能力缺口）

**证据**：`02-屏幕截图 2026-11-24 130918.png`（群聊页，右下只有一个「接力中…」按钮）

**用户原话拆解成三个独立缺口**：

| 缺口 | 具体表现 | 为什么重要（用户原话） |
|---|---|---|
| **角色不可自定义** | 群里成员的角色是预设的，不能自己定义"这个成员是谁、负责什么" | 「如果我有其他需求怎么办」 |
| **角色模型不可指定** | 不能给某个角色单独指定模型（如写文案用 A 模型、写代码用 B 模型） | 同上 |
| **不能暂停** | 接力开始后只能等它跑完，没有暂停/中止入口 | 「然后也无法暂停」 |

**第四点（用户举例，最容易被漏掉）**：**「如果要做视频怎么办」**——这暴露的不是"缺一个视频模型"，
而是**能力路由缺失**：当前群聊只按"文本对话"组织接力，没有"任务类型 → 需要什么能力 → 谁来接"的分派层。
视频、图像、长文档这类任务，光换模型名不够，需要能力声明（capability）与任务类型匹配。

**建议方向（下一轮设计，不是本轮）**：
1. 角色定义对象化：`{ name, persona, model, capabilities }`；
2. 给每个角色可独立选模型 + 可覆盖上下文/思考档（与问题 2 共用一套控件）；
3. 接力期间提供暂停/继续/中止三态；
4. 能力字段先落 `text` / `vision` / `video` / `long-context`，路由按任务意图选角色。

### 2. 设置里缺「上下文 / 输出 / 思考档位」（配置缺口）

**证据**：`01-屏幕截图 2026-11-24 131331.png`

截图里「模型、混合路由与推理」这一域只有四个字段：

```
Base URL ／ API Key ／ 模型名 ／ 温度 ／ 单会话预算(¥)
```

**实测核对**：全仓 `features/settings/` 里 grep `context|max_tokens|reasoning|thinking`
只命中 MCP 启动命令一处 ⇒ **确实没有任何上下文长度、最大输出、思考档位字段**。

**用户要的三类**：
1. **上下文长度**（context window 上限，决定能塞多少历史）；
2. **输出长度**（max_tokens）；
3. **思考档位**——因为"有的模型是有多个挡位的，如低中高或者超高/极致等待"，
   需要**内置常用档位**（如 低 / 中 / 高 / 超高 / 极致）+ **自定义思考**（自由填 token 预算或开关）。

**为什么不能只给一个数字框**：不同厂商档位语义不同（低/中/高 vs minimal/low/medium/high），
纯数字对用户不可解释；所以需要"档位 + 自定义"两层。

**建议方向**：档位映射表按 provider 维护（OpenAI 的 `reasoning_effort`、Anthropic 的 `thinking.budget_tokens`…），
UI 只暴露中文档位名，底层映射到各自参数；自定义档直接给数值输入。

### 3. 群聊接力期间只有「接力中…」，没有等待/思考动画（体验断层）

**证据**：`02-屏幕截图 2026-11-24 130918.png`——整个页面静止，只有一个按钮文字「接力中…」。

**问题定性**：这是**与主对话页的体验不一致**。主对话页有 LivingChamber 四幕（演进舱 → 思考舞台 → 正文承接 → 完成徽章），
而群聊接力期间用户看不到任何过程感——不知道是卡住了、在思考、还是在等某个成员。

**用户原话**：「群聊发送出去接力期间我只能干等着」。

**建议方向**：把主对话页的 LivingChamber 复用到群聊，但内容改为"接力"语义：
显示**当前是哪个成员在说话**、他的角色名、以及"交给下一位"的交接瞬间。
（注意与 I17「光包传递」区分：光包是交付瞬间的一次性效果，这里需要的是**持续的过程可见性**。）

### 4. 撞击动画不明显，需要重新规划

**证据**：无图，用户口述「那个撞击动画不明显，可以重新规划一下」。

**我这边的实测数据**（`tools/probe-impact-physics.mjs`，r155 之后）：

```
峰值位移 2.16 / 2.22px（两次复跑）· 收敛 250ms · 过冲 1 次 · 残余 0
```

**结论**：2px 属于**亚像素级暗示**，在 1280px 宽的窗口上基本看不出来——用户说"不明显"是被数据支持的，
不是主观错觉。当时我按"防眩晕"把它压到 2px，方向压过头了。

**建议方向**：重新定义一个"能看见但不晕"的区间，用三个量共同约束：
1. 峰值 **4–6px**（约 2–3 倍于现在），或改用**缩放**（scale 0.99）代替纯位移，缩放更易被感知；
2. 收敛仍控制在 **240–320ms**；
3. 过冲 ≤ 2 次；
4. 撞击点附近加一次**短促高光**（比现在的边缘柔光更强，但只亮 120ms）。
调完后用同一支探针复测，把新数值写回本文件。
