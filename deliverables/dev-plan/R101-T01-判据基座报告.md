### 2.2 逐条判据在测什么

| ID | 判据 | 为什么必须静态扫，不能靠浏览器 |
|---|---|---|
| A1 | 每个被 `animation`/`animation-name` 引用的名字，必须有同名 `@keyframes` 定义 | **死引用在浏览器里完全静默**：没有 console 报错，JS 读 `el.style.animationName` 仍返回那个名字，`getAnimations()` 返回空数组。运行时无法把它和「这段元素本来就没动画」区分开 |
| A2 | 同名 `@keyframes` 只能定义一次（后者静默覆盖前者） | 重复定义**不报错**，后定义的赢。两个开发者各加一份，前一份的意图永久失效且无人知道 |
| A3 | keyframes 内只准出现合成器直通属性（`transform`/`opacity`/`filter`/`box-shadow`/`background`…），出现 `left`/`top`/`width`/`height`/`margin` 判违例 | 关键帧里动 `left` 会每帧触发布局重排（layout thrash），掉帧但不报错 |
| A4 | 禁止 `transition: all` | 会把后续所有属性变更都变成动画，包括不该动的；且无法静态推断影响面 |
| A5 | 时长必须走令牌（`var(--dur-*)`），裸写 `180ms` 判违例 | 裸时长无法统一调参；改节奏要全文搜数字 |

### 2.3 两个「判据正确性」的关键决策（都是踩过才知道）

**(1) 动画名大小写敏感 —— 实测证明，不是猜的。**
用 playwright 实测：定义 `@keyframes UPPER`、引用 `animation: upper ...`，结果
`getAnimations().length === 0`。CSS 动画名**区分大小写**，`upper` 匹配不到 `UPPER`，
且浏览器不报错。所以 A1/A2 的比较全程用**区分大小写**的精确比较，不做
`.lower()` 归一化 —— 否则会把真实的死引用吞掉。

**(2) `var()` 跨度必须先剥掉再判 A5。**
`island.css:139` 写的是 `transition: color var(--dur-fast, .12s)`。第一版脚本把
`var()` 里的回退值 `.12s` 当成裸时长，报了 3 条假违例。修法不是「加个白名单」，
而是**按括号配平把整个 `var(...)` 跨度替换成等长空格**（嵌套 `var()` 也能吃），
这样 `var(--dur-fast, .12s)`、`var(--x, var(--y, .1s))` 全部不再误报。
修后：A5 从 65 → **62**，总数 96 → **93**，`island.css:139` 从输出中消失。

> 这个修法同时被复用到 A1：`animation: v4LineIn var(--dur-line, .3s)` 里的
> `.3s` 不会再被当成动画名。

### 2.4 A5 的每个声明都必须落进一个分类（会计闭合，`checked` = 各分类之和）

**先记一次自己修掉的会计漏洞**：第一版输出行写的是
`checked=375 bare=62 exempt-loop=15 exempt-kill=4 var-fallback-skipped=234`。
四个数加起来是 62+15+4+234 = **315**，而 `checked=375` —— **差 60**。
这意味着有 60 个声明**既没违例、也没被计为任何豁免**，等于凭空消失。
「豁免是计数的、不是静默丢弃」这句承诺当时是不成立的。

修法：把分类改成**互斥且穷尽**的六类，并加一条**会计不变式断言**（见 2.5）。

| 分类 | 条数 | 含义 |
|---|---|---|
| `bare-only` | **36** 个声明 | 有裸时长 ⇒ 判违例（A5 唯一的红来源） |
| `mixed` | **0** | 同一值里既有裸时长又有 `.01ms`（保留分类是为了穷尽性，将来出现不会被吞） |
| `loop`（豁免） | **15** 个声明 | 值含 `infinite` ⇒ 循环动画，令牌体系当前无循环档（架构 §6.2 已登记缺口）。`3s infinite` 里的 `3s` 是一个周期长度，不是过渡时长 |
| `kill`（豁免） | **4** 个声明 | 整个声明只有 `.01ms` ⇒ fx-off / reduced-motion 的停用写法，字面量即语义 |
| `tokenized` | **234** 个声明 | **这不是豁免，这是正确状态**：时长已经通过 `var(--dur-*)` 给了，剥掉 var 跨度后没有残留裸值 |
| `no-duration` | **86** 个声明 | 既无时长也无 var，例如 `transition: none` / `animation: none!important` —— 本来就没有时长可判 |
| **合计** | **375** | **= `checked`，闭合** ✅ |

**两个口径必须分清，不能相加**：
- `checked` / 六个分类都按 **声明** 计数，合计 375。
- 违例按 **token** 计数：36 个声明里有多个裸值 ⇒ 报 **62** 条违例。所以
  `bare-only=36` 与 `bare-tokens=62` 是同一批声明的两种计量，不是两批东西。

### 3.3 A7 的假阳性是怎么修掉的（最容易做错的地方）

第一版 A7 直接报 `:994 expertEnableBtn` 和 `:995 expertSelectBtn` 是死按钮 —— **报错了**。
这两个按钮确实是「按状态禁用」的合法控件：`frontend/src/expert/center.js` 里
`select.disabled = true; if (enable) enable.disabled = ...` 会根据选中的专家动态解禁。

第一版判法「id 字符串出现在 `.disabled =` 前后 60 字符内」失败的原因：JS 是通过
**局部变量**赋值的，`const enable = document.getElementById('expertEnableBtn')` 之后，
真正的赋值点离 id 字符串有 **200+ 字符**，60 字符窗口根本框不到。

修法：加 `resolve_state_driver()` —— 先解析「这个 id 被绑定到了哪些变量名」，
再在**这些变量名**附近找 `.disabled =` 赋值：

```python
def resolve_state_driver(src_all, btn_id):
    """判断模板里 id=btn_id 的按钮，是否在 JS 里被「状态驱动地」赋过 disabled。"""
    if not btn_id:
        return None
    names = {btn_id}
    esc = re.escape(btn_id)
    for m in re.finditer(
        r'(?:const|let|var)\s+([A-Za-z_$][\w$]*)\s*=\s*'
        r'(?:document\.getElementById\(\s*[\'"]%s[\'"]\s*\)'
        r'|\$\(\s*[\'"]%s[\'"]\s*\)'
        r'|document\.querySelector\(\s*[\'"]#%s[\'"]\s*\))' % (esc, esc, esc),
        src_all,
    ):
        names.add(m.group(1))
    for m in re.finditer(r'\.disabled\s*=', src_all):
        window = src_all[max(0, m.start() - 80):m.end() + 80]
        for name in names:
            if re.search(r'\b%s\b' % re.escape(name), window):
                return re.sub(r'\s+', ' ',
                              src_all[max(0, m.start() - 40):m.end() + 40]).strip()
    return None
```

修后结果：`A7 candidates=3 dead=1 exempt=2` —— 死 1（`:617`），豁免 2（`:994`、`:995`）。
**豁免也是打印出来的**，并附上「哪段 JS 让它合法」的原文字，不是悄悄放过。

### 3.4 A6 基线必须红，且这是真缺陷

全仓实测：`animation-play-state` **0 处**、`animationPlayState` **0 处**（CSS/JS 都没有），

窗口最小化或被别的窗口遮挡时，这 26 条循环仍在跑。这是「静置 GPU ≤ 0.5%」红线
守不住的**主因之一**（实测静置全机 p95 = 19.28%，见 §5）。

所以 A6 在 T01 基线**红得正确**。**修绿不是 T01 的事**（T01 只负责把缺陷变成可判定的红），

### 6.4 编码陷阱：`.ps1` 含中文必须带 BOM（实测，最隐蔽的一个）

**这是本轮最后抓到的一个真实 bug，必须写进报告。** 交付前脚本在 `pwsh` 7 下反复跑通，
但用文档 `.EXAMPLE` 里写的那条命令（`powershell -ExecutionPolicy Bypass -File ...`，
即 **Windows PowerShell 5.1**）执行时直接报：

```
所在位置 ...\probe_idle_gpu.ps1:104 字符: 5
+     }
+     ~
表达式或语句中包含意外的标记"}"。
```

根因：`powershell.exe`（5.1）读 `.ps1` **不做 UTF-8 探测**，直接按当前 ANSI 代码页
（本机 CP936）解码。本文件有 **62 行中文注释**，无 BOM 时 CP936 把全角括号/引号拆成
非法字节序列，引号配对错乱 ⇒ 花括号不平衡 ⇒ 第 104/106 行「意外的 }」。

**实测对照**（同一份文件，只差 BOM）：

| 状态 | PS 5.1 解析错误数 | 可执行 |
|---|---|---|
| 无 BOM（原状） | **2**（line 104、106） | 否，整文件不可执行 |
| 带 BOM（`EF BB BF`） | **0** | 是 |

**为什么之前没暴露**：`pwsh` 7 默认按 UTF-8 读，无 BOM 也正常。所以「只在 pwsh 下测过」
是这个 bug 能活到交付前的原因。

修法：文件存为 UTF-8 + BOM（工作区 13,616 B，首三字节 `EF BB BF`）。同时**改掉了头注释里
一句错话** —— 原文写「内容亦全 ASCII」，但实测非 ASCII 行有 62 行。注释与事实不符会
直接误导后来人「去掉 BOM 也没事」，所以必须改。README 已同步记录这条。

### 6.4.1 BOM 必须能过提交（team-lead 补验，我复核时改准了口径）

「本地修好了但提交后被改掉」是本仓的常见陷阱（`core.autocrlf=true` 且无 `.gitattributes`）。
入库后实测：

```
$ git cat-file blob HEAD:tools/uiaudit/probe_idle_gpu.ps1 | od -An -tx1 -N8
 ef bb bf 3c 23 0a 2e 53        ← 首三字节仍是 BOM ✅
$ git cat-file blob HEAD:... | wc -c      → 13,355
$ wc -c < tools/uiaudit/probe_idle_gpu.ps1 → 13,616
```

**BOM 存活 ✅，但字节数并不相等**：blob 13,355 / 工作区 13,616，差 **261 B 恰好等于
行数（261 行）** —— `autocrlf` 把 261 个 CRLF 归一成 LF。

⇒ 判 BOM 存在请认**首三字节**，**不要认总字节数**。这条与本仓 `harbor.html` 的纪律同源：
三种行尾约定下字节数互不相同，所以一律不写绝对字节数。我早先写「13,616 B 不变」
只在工作区口径下成立，`git cat-file` 看到的一定是 13,355 —— 已在 README 里改正。

## 7. 为什么判「rc」不够 —— 本轮的正面证据

方案要求「判据不能只看 rc」。本轮实测给出了三个具体反例：

### 7.1 死引用在浏览器里是完全静默的

`v4Spin`（`legacy.css:1281`）被引用，但**全仓 0 处 `@keyframes v4Spin` 定义**。
浏览器不会报错，`getAnimations()` 返回 `[]`，运行时无法与「本来就没动画」区分。
**只有静态扫才能发现**。同类：`v4LineIn` 29 处引用 / 0 处定义。

### 7.2 取 rc 时禁止用管道（否则 rc=1 会变成 rc=0）

`python x.py | tail` 的 rc 是 `tail` 的，永远是 0。所以一律：

```bash
python tools/uiaudit/assert_motion.py > out.txt 2>&1; echo "rc=$?"
```

这不是风格问题 —— 用管道取 rc，所有判据都会「永远绿」。

### 7.3 双门延迟失败陷阱（本仓特有，必须写进 README）

同一份「UI 契约」有**两个**检查器，读的是**两个不同文件**：

| 检查器 | 读取对象 | 后果 |
|---|---|---|
| `deliverables/design/check_contract.py` | `frontend/index.template.html`（**源**） | 改源文件它立刻红 |
| `tools/contract_diff.py` | `harbor.html`（**构建产物**） | 改了源但**没重建**，它仍然绿 |

⇒ 一个人改了模板、跑 `check_contract.py` 看到红、把改动撤回，**以为没事了**；
但只要别人在此之前重建过，`harbor.html` 已经带上了那个改动，`contract_diff` 比的是
r100 锚点，会红在一个「源看起来没问题」的时刻。

所以：**两个门都要跑，且必须先重建再跑 `contract_diff`**。只信其中一个，就会在
「看起来没问题」的时候被延迟炸掉。

### 7.4 我自己写的门里也有一个恒真门（team-lead 抓到，已修 + 已加固）

这是 T01 期间发现的**第二个恒真门**（第一个是 M6）。它比 M6 严重，因为它**藏在主判决位上**。

**现象**（team-lead 实测）：

```
PS> .\probe_idle_gpu.ps1 -TargetPid 999999 -WarmupSeconds 1 -Samples 3
→ rc=0
→ probe_idle_gpu: PASS | p95 = 0% vs threshold 0.5% (median 0%, samples 3)
```

PID `999999` **根本不存在**，却拿到了 PASS。

**根因**：滤波在采样循环里用 `continue` 跳过不匹配实例，**从不统计「命中几个」**：

```powershell
$instanceCounts += $cs.Count                                  # 整机实例数
...
if ($filterActive -and -not ($pidFilter -contains $p)) { continue }   # 跳过，但不计数
...
if ($sampleTotals.Count -eq 0 -or $totalInstances -eq 0) { Write-Blocked ... }
```

⇒ 整机有 218 个实例 ⇒ guard 不触发；但过滤后 `$sum` 恒为 0 ⇒ p95 = 0% ⇒ PASS。

**我的头部注释当时写着「必须区分 NO_INSTANCES / ZERO_ACTIVITY / MEASURED 三种状态，
不能把空集当 0%」—— 设计意图是对的，但实现只保护了「整机空集」，
没保护「过滤后的空集」。注释承诺的三态在过滤模式下并不存在。**
这是「注释与实现不一致」比「没有注释」更危险的一个实例。

**教训（这条比修复本身值钱）**：

> **空集保护要保护「你测的那个集合」，不是「存在的那个集合」。**

同类错误会在任何「先过滤再统计」的判据上重演：按用户筛选、按时间窗筛选、
按 label 筛选、按 shard 筛选……通用反例形态都是「全集非空 + 过滤后为空 ⇒ 统计值 0 ⇒ 通过」。

**修法**：单独统计 `$matchedCounts`，三态顺序写死。

| state | 条件 | 结果 |
|---|---|---|
| `[1/3]` | 整机实例数 == 0 | blocked（驱动不上报 / 无 3D 活动，不可分辨） |
| `[2/3]` | `filterActive && 匹配实例数 == 0` | **NO_INSTANCES → blocked, rc=2** ← 本次修的洞 |
| `[3/3]` | 走到这里 | MEASURED，按 p95 判 PASS/FAIL |

⇒ **「输出里出现 PASS」等价于「确实匹配到了目标实例」。** 这是可被断言检验的**强性质**，
也是负控该断言的东西 —— 断言 rc 不够，因为「rc=2 但输出仍有一行 PASS」这种
**半修状态**最容易发生。

同时 `-Json` 输出新增 `scope` / `targetPids` / `machineInstances` / `matchedInstances`，
让「p95=0%」能与「测不到」在机器可读层面分开。

**固化成脚本**：新增 `tools/uiaudit/probe_idle_gpu_selftest.ps1`，四组对照。

| 组 | 输入 | 期望 | 实测 |
|---|---|---|---|
| A | 假 PID `999999` | rc=2 + `NO_INSTANCES` + **判决行数 = 0** | ✅ |
| B | **真实存在但无 3D 实例**的进程（自身 `$PID`） | 同上 —— Q13 的 N₀ 语义 | ✅ |
| C | 不带 `-TargetPid` | MEASURED + **判决行数 = 1**（主路径未改坏） | ✅ |
| D | 真实 Harbor 进程树（28 pids） | MEASURED + **判决行数 = 1**，`matched>0` | ✅ 46 实例/采样 |

**B 组是最有说服力的一条**：原缺陷对「进程存在、但它没有 3D 活动」这种**完全正常的
N₀ 场景**同样会静默变绿 —— 而那正是 Q13 用来验证「探针作用域没泄漏」的判据。
一个会把 N₀ 判成 PASS 的探针，等于**没有作用域保护**。

**判据形态被 team-lead 纠正过一次，值得记下来：不要用关键词匹配判决，要用结构匹配。**

我第一版写的是 `-ForbidSubstring 'PASS'`（全文不含 `PASS` 字样）。这个判据**是错的**：

- 说明文字里出现「PASS」是**合理的** —— `"Refusing to report 0% as a passing measurement"`
  正是在**解释它为什么不出 PASS**。关键词判定 = **把解释当成结论**。
- PowerShell 的 `-match` **默认不区分大小写**（`-cmatch` 才区分），所以 `-match 'PASS'`
  会命中 `passing` / `passed` —— 这一条本身就制造假阳性。

正确判据是匹配**判决行的结构**：

```powershell
$verdict = @($out -split "`n" | Where-Object { $_.Trim() -match '^\S+: (PASS|FAIL) \| p95' })
# blocked 组要求 $verdict.Count -eq 0；MEASURED 组要求 -eq 1
```

只有探针自己的 `Write-Verdict` 会产出这种行，所以它是**充分且特异**的。

实测分辨力（不是断言它「应该有」，是跑出来的）：

| 场景 | 判决行数 | 结果 |
|---|---|---|
| 修复后 A 组（假 PID） | **0** | PASS |
| 修复后 B 组（整机口径） | **1** | PASS |
| **重注入缺陷后 A 组** | **1** | **FAIL**（`verdict-line count=1 want=0`） |

**纪律（与本仓「规则/说明行禁复用判决量 KEY」同源）**：

> **判据不要匹配说明文字里的关键词，要匹配判决行的结构。**

**并且这道自检本身也验过会红**（否则它自己就是新的恒真门，与 M6 同源）：

把 `if ($filterActive -and $totalMatched -eq 0)` 改回 `if ($false)` 重注入原缺陷 ⇒
自检立刻 `2 PASS / 2 FAIL`，并自动打印三条问题 +
被探测针完整原始输出（含那行 `PASS | p95 = 0%`）：

```
gpu_selftest A [FAIL] fake PID 999999 -> NO_INSTANCES (was: silently PASS) (rc=0)
  -> rc=0 want=2; missing 'NO_INSTANCES'; verdict-line count=1 want=0 (blocked 组不该有判决行)
gpu_selftest A   | probe_idle_gpu: PASS | p95 = 0% vs threshold 0.5% (median 0%, samples 3)
gpu_selftest: 2 PASS / 2 FAIL / 0 SKIP
gpu_selftest: FAIL | scope negative-controls must all go blocked; a passing fake PID
  means the probe is tautological
```

恢复后回到 `4 PASS / 0 FAIL, rc=0`。

**顺带修掉的两个自身 bug**（都在自检脚本里，都是「跑出来才发现」）：
1. **PowerShell `-f` 运算符优先级**：`("a{0} " + "b{1}" -f x, y)` 实际被解析成
   `"a{0} " + ("b{1}" -f x, y)` ⇒ 前一段的 `{0}` 永不替换，输出里留下字面量 `{0} {1} {2}`。
   修法：先把格式化结果存进变量再拼接。
2. **函数内 `Write-Output` 会混入返回值流**：`$results += Test-Expect ...` 会把
   `Write-Output` 打出的字符串**一起收进数组** ⇒ 明细行永远打印不出来（只有汇总行）。
   修法：判定函数只 `return` hashtable，由调用方打印。

这两条都是「PowerShell 与常规语言语义不同」的坑，已写进 README 的陷阱清单。

`infinite` 循环转圈，与 A6 那条线耦合）。

`v4LineIn` 侧：只需补 1 个定义就能覆盖 29 处引用，但有 **4 种 token 组合**
（`out-soft+both` ×13 / `out-soft` ×10 / `anticipate` ×4 / `dur-narr` ×2），
需架构确认一份定义能否通吃 —— 详见 §11-3。

### 10.2 `access-strip` 是 52px 里的主体（44px），方案叙述与实际构成不符

实测两个状态的行高（`--json` 输出的 `rows`）：

| 行 | current | baseline | 差 |
|---|---|---|---|
| `attach-preview` (`#attachPreview`) | 0 | 0 | **0**（当前 `display:none`） |
| `ws-quick` (`#wsQuick`) | 0 | 0 | **0**（当前隐藏） |
| `access-strip` | **44** | 0 | **−44** |
| `input-row` | 62 | 62 | 0（输入框本体不动） |
| `hub-chip` (`#hubChip`) | 0 | 0 | 0（当前隐藏） |
| **合计（输入舱高度）** | **186** | **134** | **−52** |

读法：
- 三层「可选控件」里 **两层当前高度就是 0**（`attach-preview`、`ws-quick` 已经是隐藏态），
  收走它们**拿不到任何空间**。
- 52px 里 **44px 来自 `access-strip` 单层**，剩下 **8px 来自折叠后的间距/边框重算**。
- 所以方案「隐藏三层可选控件得 56px」这个叙述**与实际构成不符** —— 真正要动的是
  `access-strip` 这一层。这也解释了为什么实测 52 < 估计 56：估计是按三层都收走算的，
  实际只有一层有高度。

**对 T03 的直接影响**：如果产品真的要「释放 56px」，光隐藏 `access-strip` 只能拿 44px，
必须另外再找 12px（比如压 `input-row` 的 62px，或收掉 `hub-chip` 若哪天它显示出来）。
这是产品决策，不是工程能自己补的差额。

### 10.3 `v4Spin` 是 `infinite` 循环 —— 与 A6 那条线直接相关

`legacy.css:1281` 那一条：

```css
.plan-step.doing .st{border-color:var(--primary);border-top-color:var(--primary-soft);
  animation:v4Spin var(--dur-stream) linear infinite}
```

三个细节，每个都影响修法：
- **`infinite`** ⇒ 它**已经被算进 A6 的 26 条里**（A6 是按 `animation:...infinite`
  文本计数，不看定义是否存在 —— 实测确认 `legacy.css:1281` 在 A6 的计数集合内）。
  但因为它没有 `@keyframes`，**今天这条其实根本没在转**。也就是说 26 条里
  有 1 条是「账面循环、实际静止」，真实在跑的是 **25 条**。
  ⇒ 一旦按 A1 的修法补上 `@keyframes`，**第 26 条会真的开始转**，静置 GPU 只会更差。
  所以「补定义」与「加暂停钩子」必须**同批做**，否则 A1 修绿换来的是 GPU 更红。
  这也是 A1 和 A6 不能分给两个人做的原因。
- **`var(--dur-stream) linear infinite`** ⇒ 时长走令牌、线性、无限，是典型的 loading 转圈。
  这类动画本来就该在 `visibilitychange` 时停。
- **只有 1 处引用** ⇒ 也可以**直接删掉 `animation`**，改用静态边框态。这是产品取舍
  （转圈 vs 静止），不是工程能单方面定的。

### 15.2 ⚠️ 但 §5.3「做法 A（零漂移）」是**错的**，会直接坑到 T02

架构文档 §5.3 写：

> **做法 A（推荐，零漂移）**：新增 `<button class="rail-btn" data-panel="insight" …>`，
> **不带 id、不带 onclick**，由 `panels.js:18` 的 `querySelectorAll('.rail-btn[data-panel]')`
> **自动接管**；⇒ `html.dom_ids` / `onclick_fns` **均不变**。

**「自动接管」不成立。** `panels.js:18` 那一段只做**高亮同步**，不挂任何点击监听：

```js
function switchPanel(name) {
  if (!PANELS.includes(name)) return;
  const prev = currentPanel; if (prev === name) return;
  currentPanel = name;
  document.querySelectorAll('.rail-btn[data-panel]').forEach(btn => {
    btn.classList.toggle('on', btn.dataset.panel === name);   // ← 只翻 class
  });
  ...
```

全仓证据（四条独立交叉验证）：

| 验证 | 结果 |
|---|---|
| `grep -rn "data-panel" frontend/ --include=*.js`（排除打包产物） | 全仓只有 **2 处**：`panels.js:18` 与 `:19`，都是高亮同步。**没有任何装点击的地方** |
| 有无 `#rail` / `.rail-btn` 上的 `addEventListener` 或事件委托？ | `grep closest('#rail'` / `querySelector('#rail')` / `.rail` delegation → **0 处** |
| 对照：同类「无 id 靠 data-* 驱动」的控件怎么接线的？ | `shell/hub-market.js:169` 对 `[data-hm-tab]` **显式** `querySelectorAll(...).forEach(b => addEventListener)`；`:373` 还用 `closest('[data-hm-tab]')` 做委托 ⇒ **说明本仓惯例是「必须有人显式绑」，不是 DOM 自己会响应** |
| **构建产物自查（最硬的证据）** | `harbor.html` 的 `<nav class="rail">` 内 **14 个按钮，无一例外**：要么有 `onclick=`，要么有 `id=` 由 JS 绑。**没有一个只靠 `data-panel` 承<sup>1</sup>** |

<sup>1</sup> 若「做法 A」成立，现有那 3 个 `data-panel` 钮（`:95/:96/:97`）根本不需要再写
`onclick="switchPanel(...)"` —— 正因为没人委托，它们才必须各写一次 onclick。

**推论**：新增一个「无 id、无 onclick、只有 data-panel」的 rail 钮，结果是
**它长得像按钮、能高亮，但点了什么也不发生** —— 正好是本轮红线要消灭的
「假按钮」形态（与 A7/A8 同类）。**判据 `assert_dead_controls.py` 抓不到它**
（A7 只看 `disabled`，A8 只看 JS 生成的 `disabled`）⇒ 这类缺陷目前**无判据覆盖**。

**还有第二个坑：新面板的 id 跑不掉。** `switchPanel()` 靠
`document.getElementById('panel' + name[0].toUpperCase() + name.slice(1))` 找容器
⇒ `data-panel="insight"` 要求模板里有 `id="panelInsight"`，而 `contract_diff.py:84`
的正则**会把这个 id 抓进 `html.dom_ids`** ⇒ `dom_ids` 漂移是**不可避免的**，
只是「多一颗 id」还是「多一组 id」的问题。「零漂移」这个承诺**在这个功能上不成立**。

| **C（真零漂移）** | 不给新钮，把 `#panelAnalytics` 现有容器复用作「记忆与洞察」，并给 `switchPanel('analytics')` 补一颗 `data-panel="analytics"` 的 rail 钮 | 复用现成 id，**不加新 id** | **零**（`analytics` 已在 `PANELS` 数组内，`showPanel` 链已通） | 但注意：新钮仍必须带 `onclick="switchPanel('analytics')"`（**这正是 15.2 的直接推论**）——所以它仍不是「无 onclick」，只是 `switchPanel` 已在前导名集合内 ⇒ 计数 5→6，**不漂移** |

**我的建议（供架构裁定，不擅自改）**：走 **C**。它在**当前证据**下是唯一真零漂移的，
且 `panelAnalytics` 已是 `PANELS` 成员、`switchPanel` 已在契约集合内 —— 只需
`data-panel="analytics"` + `onclick="switchPanel('analytics')"`，契约面一个字节都不动。
若产品坚持要独立的「记忆与洞察」容器，则必须接受 A′/B 的 `dom_ids` +1 并推 r101 基线
（那就不再是「零契约变更」，§5.3 的结论要跟着改）。

### 15.4 一条给 T02 的通用防呆
