# R101-M2-D1 · `R_nonZeroFrame` 实测结论（一页）

探针：`native/build/m2probe/d1_r_probe.cpp`（+ `d1_r_overlay.js` / `d1_r_preload.js` / `bd1r.bat`）
形态：原生 DComp 背板窗 + Electron 透明覆层窗，同 rect（330,270 480×360）完全重叠；
两层各画 8 码元条（背板 64,64 / 覆层 96,104，空间分区不重叠），6bit 载荷 + 2bit CRC-2；
DDA 一次 `AcquireNextFrame` 在同一块桌面快照上同时解两层 → Δframe。

## 1. 核心结论（一句话）

**`R_nonZeroFrame` 不是可复现量：同一配置 7 次跑出 0.31% ~ 100%（320 倍跨度），
由两侧流水线的亚帧相位驻留决定，与「两层是否耦合」无关。它不是区分力不足，是**
**不可作为判据。**

## 3. 三件套结果

| 项 | 结果 | 判读 |
|---|---|---|
| **应绿**（不注入） | R = 0.003 / 0.025 / 0.037 / 0.201 / 0.504 / 0.972 / 1.000 | **不成立**：不存在"一个小而稳的基线 R"，同一配置全域乱跳 |
| **正样本**（注入 1 帧级滞后） | `P(\|Δ\|≥2)` 0.0014 → **0.2554（182×）**；12 个 5s 桶逐桶 R=0.750±0.004 | **成立**：解码链分辨力完好、注入确实生效、读数完全平稳 |
| **负控**（两者必须显著不同） | 注入 R=0.751，但**不注入内部**就有 0.504↔0.972 的差（0.47），大于注入带来的变化；且 0.972→0.751 方向为负 | **失败**：统计量的自身噪声 > 它要测的信号 |

结论：**仪器是好的，统计量是坏的。** 注入试验证明码元链路能把"覆层滞后 3/4 帧"精确读成 0.750；
而"不注入"这一支根本无法给出稳定的基线，所以 R 的任何一次读数都不可解释。

## 4. 架构师的 [0.5%, 15%] 是否被支持

**不被支持。** 实测落在该区间的只有 rep1(2.5%)、rep3(3.7%) 两次；rep2 为 0.31%（区间下方），
而 base60#1(50%)、base60#2(97%)、selftest(100%) 高出区间上界 3~200 倍。
该区间只是宽分布里的一次随机抽样，不是可复现的物理量。

**同时实测支持架构师的机制直觉，但推翻它的可测性**：两层被 DWM 锁在**同一 vsync**上，
Δframe 长时间是**常数整数**（0 或 +1；驻留占比 96~99.7%，最长 11~14s 不翻），
翻动只是亚帧相位越过 vsync 边界（|Δ|≥2 仅 0.1~0.2%，不是掉拍）。
所以"两个互不通信的调度器"在**相位上并不独立**，只是流水线深度差一个整数帧；
这个整数差（0 还是 1）取决于启动瞬间的相位，**无法在单次采集里定标**。

## 5. 对方案的影响

- **不要展开 Δframe 这条线**：架构师 v2（§0.3 第 46 行）已把 `R_nonZeroFrame` 撤回、
  把 Δpx/Δframe 记 `blocked(reason=capability)`。本次实测给出更强的结论：
  不是"测不到"，而是"**测得到但没有分辨力**"——按它的结果无论耦合与否都会给出 0.3%~100%。
- **继续用 `coupleRatio`**（架构师 §2.2）：对齐无关、计数比对、实测二值分离 53×。
  > **口径更新（T04 落地后）**：`53×` 是本文写作时的 8s 轮口径（`injectCount=52`，`1.0192/0.0192`）。T04 改为 60s 轮（`injectCount=395~396`）后，分离度是 **`1.010101/0.015152 = 66.67` 倍**（保守 `100.00` 倍，余量 `3.300`/`2.020` 倍），见 `r101-evidence/d1/aggregate.json` 与 `R101-M2-c-裁决报告.md` §G.2。两值不矛盾，但要写清方向：8s 轮是 `1/52 = 0.0192`，60s 轮最好那轮是 `6/396 = 0.0152` —— **分子涨 5 倍（1→6）而分母涨 7.6 倍（52→396）**，所以独立侧下界反而更低、分离度从 `53×` 升到 `66.67×`。**加长窗口对独立侧是净改善**（分母涨得比分子快）。写报告时**用 66.67**，`53×` 只作历史沿革。
  本轮没有提供任何需要回到 Δframe 的理由。
- 若将来仍要像素级 D1，唯一平稳的替代量是 `DFRAME_MODE_SHARE`（主值驻留）+ 注入前后的
  `FLIPS_PER_SEC`（0.6~4.5/s → 164/s，36~270× 分离）。但那需要重新走三件套，
  且不解决"同样配置不同相位"的定标问题。**建议不重开。**

## 6. 本轮新增的坑（建议进记忆）

1. **`R` 这类"两个采样量是否相等"的统计量，在两侧都被同一个 vsync 锁相时是二值+漂移量**，
   不是比例量。它的期望值由启动相位决定，采集窗口再长也只覆盖有限相位。
   任何"P(Δ≠0)"类指标都必须先做**跨进程重复性**（同配置跑 ≥3 次），否则会把相位伪影当信号。
2. Electron 透明无边框窗的 `getContentBounds()` **不等于**请求的 rect：请求 480 物理 px
   （320 DIP × 1.5）实得 **483**（322 DIP × 1.5）。原点精确，宽度多 3px。
   ⇒ 覆层几何必须**回读**并写日志，不能假设 `phys == 请求值`。
3. 跨进程时基：`process.hrtime.bigint()`（libuv 在 Windows 走 QPC）与原生 `QueryPerformanceCounter`
   **同一时基**，可直接把 `t0` 从原生传给 Electron。但页面上拿不到 `process`，
   必须经 `preload + contextBridge` 暴露（`sandbox:false`）。
   `performance.now()` 的 `timeOrigin` 是墙钟推导，误差 ~1ms = 一个 vsync 的 16%，不能用于 1/4 帧相位判定。
4. 时钟自证的正确判据不是"差值≈0"：`t0`（spawn 前）与 `READY_NS`（首帧后）天然差 **0.46~1.02s（小负数）**。
   写成 `|diff|<1s` 会误报 MISMATCH。
5. 全黑必须判"无效"：全黑解出 payload=0 + CRC=0 会**通过校验**变成 frameIdx=0。
   编码取 `V=(frameIdx mod 63)+1`，0 保留 —— 这是本探针唯一对规格的偏离（状态数 64→63），
   不加这条，没读到内容会被静默读成"Δframe=0"（假绿）。
6. 空闲窗口不泵消息 >5s 有被 DWM 判无响应/停合成的风险（会伪装成 DDA 抓不到）；
   主线程轮询期间顺手 `PeekMessage` 即可。
7. 同一时刻只能有一个 DDA 会话（`DuplicateOutput` 冲突），探针不能并行跑。
8. 矩形填充用 `ID3D11DeviceContext1::ClearView(rtv, color, rects, n)` 即可，不必写 shader。
