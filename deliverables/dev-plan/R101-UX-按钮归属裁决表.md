## 一、先纠正计划书的一个算术错误

计划书 T02 出口写：「主链路组 **4 颗** + 底部系统组 **5 颗**，`.rail-btn` **合计 8**」。

**4 + 5 = 9，不是 8。** 浏览器实测（`#rail` 内 `querySelectorAll('button')`）：

```
#rail 内 button 总数        14
其中 class 含 rail-btn      9      ← 与「4 + 5」一致
其余 5 个是 mn-btn（子菜单项，不是 Rail 成员）
```

⇒ **正确值是 9**。计划书里的「8」是笔误，`旧写法「Rail 成员清单 = 5」也不可测`（实测 9）。
本表按 9 记录。

## 三、一级入口目的地清单（5 个）

对话 / 能力中心 / 项目与文件 / 记忆与洞察 / 设置。

**为什么是 5 而不是 9**：剩下 4 颗（工具箱 / 通知中心 / 余额 / 主题）是**动作**不是**目的地**——
它们分别打开浮层、切换主题、打开账单、切通知，不构成"页面级去处"。
计划书把「入口目的地清单 = 5」和「`.rail-btn` = 9」并列，两者不矛盾，量的是两件事。

## 六、最重要的一条：`relocate` 是三条件

本轮实盘教训（`#panelSessions`）：

1. 删掉 Rail 的「会话历史」钮 → 全仓再无 `switchPanel('sessions')`；
2. 而 `#panelSessions` 的 id 还在、里面 4 个 `setSessionFilter` 字面量也还在；
3. ⇒ `check_contract.py` **PASS**、`contract_diff --compare` **零漂移 PASS**；
4. 但那个面板**永远不显示**，其内的会话类型筛选与会话概览**没有任何其它入口** ⇒ 功能真丢。

**所以 `relocate`（换宿主保留功能）必须同时满足三条：**

| 条件 | 能否被门禁保证 |
|---|---|
| ① id 字面量仍在模板/产物里 | ✅ `contract_diff` 的 `html.dom_ids` |
| ② onclick 前导名仍在集合里 | ✅ `contract_diff` 的 `html.onclick_fns` |
| ③ **新宿主真的能点到** | ❌ **无门禁可自动保证**，只能人工裁决 + 运行时探针 |

第 ③ 条是这张表存在的根本理由：**契约会计判得出"东西还在"，判不出"还有没有人能到达它"**。

## 七、契约会计的余量提醒

以下 onclick 名在 R101 契约会计时**余量为 1**（模板里只出现 1 次），删任一立刻红；
改模板后请重新计算，不要沿用旧数：

```
toggleTheme / toggleSidebar / openBilling / toolsToggle
navToggleNotify / renderAnalytics / scOpen / spManualOpen
```

另有两处口径要注意：
- `contract_diff` 的 onclick 正则**只取属性里第一个函数名**：`onclick="switchPanel('x');foo()"`
  只算 `switchPanel`，第二个调用不受保护。
- `html.onclick_fns = 54` 而模板侧只有 47：差的 7 个全部来自**内联 JS 字符串里拼的 HTML**
  （如 `controller.js` 的模板串）。⇒ 改「JS 里生成的 HTML」与改模板同权。
