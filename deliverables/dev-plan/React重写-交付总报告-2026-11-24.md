## 八、r10 自带测试套件的修复（2026-11-24 16:55）

r10 交付时**自己的测试是红的**（单测 23/25、e2e 直接崩）。三条都修了：

### 1. 单测 25「主持人调度构建与动态重排」—— 实现缺陷，已修

**现象**：兜底路径只返回 2 人（架构师、实现工程师），把 `ui设计` 与 `代码审查员` 丢了。

**根因**：`parseModeratorPlan` 的兜底用**空意图**去调路由：
```js
const fb = fallbackRouted || routeGroupMembers('', list, 'smart', '')
```
空意图等于"按空条件筛人"——`m_ui`（无 capabilities 字段）与 `m_qa` 被静默剔除。
**后果是用户可见的**：模型输出 JSON 不可用时，班组从 4 人缩到 2 人，界面不会提示。

**修法**：兜底改为**保留全员**，按 `workflowStageRank` 排序（规划→架构→UI→实现→审查），
并补上 `intent.label`（下游要读 `fb.intent.label`，否则会 `Cannot read properties of undefined`）。

### 2. 单测 12「缺失时诚实预警」—— 陈旧前提，已修

r10 的警告文案从"名册中暂无声明该能力的角色"改成通用句
`当前议题暂无单一专长匹配，已智能编排全员（3 位）协同接力。`
测试仍在断言 `includes('视频制作')`，故红。

**修法**：判据改为"必须有诚实提示"（非空 + 匹配 `暂无|全员`），不绑定具体措辞。

**一并记录（未修，属产品口径）**：文案**不再点名缺失的能力**，
用户不知道缺的是"视频"还是"音频"——这是可用性退化，建议 r11 把能力名加回。

### 3. e2e 桩 `ERR_HTTP_HEADERS_SENT` —— 用例缺陷，已修

`tests/e2e-r3-regression.mjs` 的聊天 SSE 分支在 211 行已统一 `writeHead`，
「主持人重排」子分支在 227 行**又写了一次**，同一请求写两次头直接抛异常，整套 e2e 崩在这里。

**修法**：删掉重复的 `writeHead`（头已发，只需写 body），并加注释说明原因。
