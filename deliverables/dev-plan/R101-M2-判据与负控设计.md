# R101-M2 判据与负控设计（T06 定稿）

> **地位**：本文件是 M2-c 裁决的**唯一判据事实源**。PRD 给「测什么/为什么测」，本文件给「怎么判/判错了怎么发现」。
> **约束**：本文件每个判据常量必须有 ①来源 ②依据 ③重标定触发条件，缺任一不得进实现（PRD 判据常量元规则）。
> **新增强制条款**：本轮实测发现两类「指标全绿而结论完全错」，故新增**元规则第四条：任何绝对值类判据必须附「分辨力证明」**（见 §0.3）。

---

## §0 元规则

### 0.1 判据常量三件套（PRD 原规则）

每条判据常量必须写全：
1. **来源**：实测 / 判据设计（无实测依据）/ 契约常量 / 外部标准
2. **依据**：为什么是这个数
3. **触发重标定条件**：什么情况下必须重核

**缺任一条 → 该常量不得进实现。** 实现里出现无来源的数字，代码评审直接拒。

### 0.2 负控期望值必须物理隔离

负控（negative control）的期望值与主判据的常量**不得共处一个可编辑单元**。具体要求：
- 不共用同一个常量/变量/配置项
- 负控侧写**独立字面量**（不是 `THRESHOLD * 2` 这种派生写法）
- 负控侧必须带来源标注（`// NC-A1 expect: 0.15ms 级，来源=R101 实测 calib.cpp CAL-3`）

**理由**：若负控期望 = 主判据常量派生，那么"调低主判据"会同时调低负控期望，负控永远抓不住。这是「判据补丁本身有洞且更隐蔽」（教训 17）的变种。

### 0.3 🔴 元规则第四条：统计量分辨率（本轮新增，PM 与主理人两条表述合并）

任一统计量进入 Δ/N 比较前，必须同时满足两件事：

1. **声明分辨率（量化步长）** —— 该量在本机当前刷新率/负载下的最小可分辨台阶
2. **证明该步长小于待分辨差异** —— 用「空对照」或「负载扫描」给出实证

任一条不满足 → **该统计量退出 Δ/N**，由其它统计量承担，**不得因「测得相等」而记 `tie`**。

**分辨力证明的标准形式（二选一）**：
- **空对照**：0 负载 vs 最小负载，读数必须出现可辨差异（例：GPU 墙钟 0 次 Clear = 0.0005ms vs 8 次 = 6.05ms）
- **负载扫描**：≥3 档递增负载，读数必须单调或有明确台阶（例：Clear 8→640 全平 = 无分辨力）

**本条的实证来源（R101 E15）**：GPU pass 墙钟在 165Hz 满帧节拍下被量化成 `k×6.06ms`；8→640 次 Clear（80 倍负载）读数极差仅 0.9%，越界直接跳 2×。若只做单点比较，会得出「Δ=0 → tie」的结论，实际是「仪器没分辨率 → 必然 tie」。

**为什么这条比前几类更重要（PM 的分类 + 主理人补充）**：

| 类型 | 表现 | 危害 |
|---|---|---|
| 第一类 编数字 | 数据是假的 | 报告失真，但可被交叉校验抓 |
| 第二类 假绿 | 指标全绿、功能未成立 | 导向「修 bug」，**修复方向是对的** |
| **第三类 假 tie** | **两个量测得相等** | **导向「随便选一条」—— 决策错误，不只是报告错误** |

假绿至少会逼你去查；**假 tie 长得完全像正常结论，没有任何负控会报警，而且会直接产出一个错误的选型决定**。例：「A 慢 0.8ms 但仪器分辨力是 6ms」→ 报告写「不可区分」→ 选 A → 上线后发现慢。这是本 Spike 最需要防的第三类造假。

## §1 D2 判据（单帧开销与节拍）

### 1.1 主统计量定义（**已按 E15 修正**）

| 量 | 定义 | 是否参与 Δ 比较 | 依据 |
|---|---|---|---|
| **PRESENT_P50** | Present→Present 间隔的 p50 | **是** | 主统计量。`SyncInterval=1` 下等于 vsync 周期，是正确语义 |
| **PRESENT_P95** | 同上 p95 | **是** | 尾部延迟，抖动敏感 |
| **PRESENT_P99** | 同上 p99 | **是** | 掉拍判据的输入（D2②） |
| **PRESENT_MAX** | 同上 max | 仅旁证 | max 受首帧/resize 污染，不作 Δ 输入 |
| **DROP_RATE** | `interval >= 2×vsyncBase` 的比例 | **是** | 掉拍率，分辨率 = 1 拍 |
| **SUBMIT_MS** | 帧起点 → `Present1` 之前 | **是** | **真正**的 CPU 纯开销。实测 p50=0.0759ms@165Hz |
| **FRAME_MS** | start-to-start 整圈墙钟 | 仅旁证 | pacing 量，`SyncInterval=1` 下收敛到 vsync 周期 |
| **WAIT_MS** | `WaitForSingleObjectEx` 内阻塞 | 仅旁证 | 与 FRAME_MS 一起构成恒等式：`SUBMIT+WAIT<=FRAME` |
| ~~CPU_PER_FRAME~~ | ~~进程 CPU 时间/帧~~ | **否（废止）** | **⚠ 实测该名曾指代整圈墙钟**（报 6.0643ms ≈ 165Hz 6.0594ms），真实 CPU 开销仅 0.0759ms。两链都被 vsync 钉住 ⇒ **必然假 tie** |
| **PRESENT_COUNT_PER_SEC** | Present 次数/秒 | 仅结构性旁证 | D2⑤ |
| ~~GPU_WALL_MS~~ | ~~GPU pass 墙钟~~ | **否（降级）** | **E15 判定无分辨力**，仅报 k 档 |

### 1.2 各判据常量

| 常量 | 值 | 来源 | 依据 | 重标定触发 |
|---|---|---|---|---|
| `VSYNC_BASE` | **实测帧间隔中位数**（运行时算，非写死） | PRD D2② | 本机 165Hz 实跑 p50 = 6.0594~6.0643（6 组 × 180 帧，E14b/CAL-2~CAL-6），相对理论 6.0606 偏差 ≤0.06%。用实测中位数可容忍标称刷新率达不到的情况 | 换显示器/改刷新率/改 DPI 缩放 |
| `PACE_TOL` | **0.20** | 判据设计（有实测支撑） | `\|p50 − 1000/hz\|/(1000/hz) ≤ 20%`。实测 `SyncInterval=1` 偏差 0.06%、`SyncInterval=0` 偏差 96%+ ⇒ 20% 阈值对二者有 30 倍分离度 | 若出现合法的 ±20% 以上节拍差（如 VRR 场景），须重核 |
| `DROP_FAIL_P99` | **`p99 >= 2 × VSYNC_BASE` 且 3 轮均出现** | PRD D2② | 周期性掉帧不是噪声。实测掉一拍即 12.11ms（=2×6.06），台阶清晰可辨（E15 负载扫描 640→768 次直接跳到 12.11） | 若出现 1.5 拍等非整数档（VRR/LFC），须重核 |
| `GPU_VALID_RATIO` | **≥90%** | PRD P0-5 / R5 | 实测按 `SyncInterval=1` + Waitable 推进：99/100 = 99%（E14b 修正后）。紧凑循环仅 1%（E14 v1） | 采集器更换统计方式 |
| `GPU_TIER_K` | 只报 `k = round(p50 / VSYNC_BASE)`，**不报绝对值** | E15 实测 | k=1 满帧 / k=2 掉一拍 / k≥3 长空洞。**禁止用 k 做 Δ 比较** | — |

### 1.3 D2 负控

| ID | 注入 | 期望 | 判据被验证到的是什么 |
|---|---|---|---|
| **NC-D2-1** | `Present1(1,…)` → `Present1(0,…)` | `PRESENT_P50` 从 6.06ms 级**跌到 0.15ms 级**，`PACE_OK` 必红 | **节拍判据真的在测 vsync**（不是恒真）。来源：CAL-1/CAL-3 实测 0.1536/0.1537ms |

## §5 采集器字段全集（P0-5 定稿）

每帧一行 JSONL，字段不可缺（缺任一 → 该行作废，不计入统计）：

```jsonc
{
  "runId":        "r101-20261121-0345-A-01",   // P0-1 指纹
  "commit":       "<采集器 git hash>",
  "collectorVer": "1.0.0",
  "pathway":      "A",                          // A | B
  "tier":         "165",                        // 165 | 60，两档分别落盘
  "frameIdx":     42,                           // 递增，缺号即掉帧证据
  "qpcPresent":   12345678901234,               // QueryPerformanceCounter 原始值
  "intervalMs":   6.0594,                       // 与上一帧的差，ms
  "submitUs":     75.9,                         // CPU 纯提交开销：帧起点 -> Present1 之前，µs
  "frameUs":      6053.0,                       // start-to-start 整圈墙钟，µs（pacing）
  "waitUs":       5835.0,                       // WaitForSingleObjectEx 内阻塞，µs（-1=未测）
  "gpuPassUs":    6054.0,                       // GPU pass 墙钟，µs；gpuValid=0 时写 -1
  "gpuTierK":     1,                            // round(gpuPassUs / vsyncBaseUs)，仅旁证
  "gpuValid":     1,                            // 0 = 时间戳未读出，不得计入 GPU 统计
  "presentCount": 42,                           // GetLastPresentCount 累计值（D2⑤ 旁证）
  "dpiAware":     "PER_MONITOR_AWARE_V2",       // E16b 必须显式记录
  "syncInterval": 1,                            // E14b 必须显式记录，写 0 即判采集器无效
  "waitable":     1,                            // 是否 WaitForSingleObjectEx 推进
  "clearsPerFrame": 8                           // 负载档位（空对照=0，供 E15 的 k 档判读）
}

> **⛔ 已废止字段 `cpuUs` / `CPU_PER_FRAME`**：R101 实测该名曾指向两个物理量——累计时钟差分（=整圈墙钟，
> 报 6.0643ms ≈ 165Hz 的 6.0594ms）与 CPU 纯提交开销（实测 **0.0759ms，差 80 倍**）。两者都能给出
> \"合理\"读数，且都是同一段代码。**一个字段只能对应一个物理量、一个采集区间**（元规则第五条）。
> 任何文档、报告、脚本若仍出现 `cpuUs` / `CPU_PER_FRAME`，视为未更新。
```

**强制校验（采集器自身必须自检，不通过就拒绝出报告）**：
1. `syncInterval` 必须为 **1** —— 为 0 则整份数据作废（E14b）
2. `waitable` 必须为 **1** —— 为 0 则整份数据作废（E14 v1 教训）
3. `dpiAware` 不得为 `UNAWARE` —— 否则坐标类判据作废（E16b）
4. `gpuValid=1` 的比例 ≥ **90%**
5. `frameIdx` 必须连续（缺号数 = 掉帧数，用于交叉校验 `DROP_RATE`）

## §6 噪声基线 N（P0-13 定稿）

### 6.1 定义

对每个通路、每档刷新率，重复 **3 轮 × 60s**（同负载、同参数、同采集器版本）。N 定义为**三轮同统计量的极差**：

```
N(stat) = max(round1[stat], round2[stat], round3[stat])
        - min(round1[stat], round2[stat], round3[stat])
```

**必须落盘的统计量**：`PRESENT_P50`、`PRESENT_P95`、`DROP_RATE`、`SUBMIT_MS_P50`（CPU 纯开销）、`FRAME_MS_P50`（pacing）、`Δpx` 的 `p95`。（`CPU_PER_FRAME` 已废止，见 §5 说明：它曾同时指代这两个量。）

### 6.2 为什么是极差而不是 σ

3 个样本算标准差没有统计意义（σ 的置信区间在 n=3 下极宽）。**极差是 3 个样本能给出的最诚实离散度**。用 σ 会让人误以为有统计严谨性。

### 6.3 硬约束

| 约束 | 内容 |
|---|---|
| **N 必须来自本机** | 不许文献值、不许别的机器、不许估算（PRD R-4） |
| **N 必须在同节拍下取** | 采集节拍不同（`SyncInterval` 不同、Waitable 有无不同）→ N 是假的，Δ/N 全部失效（PRD R-4 + E14b） |
| **N 缺失 → 不出终稿** | 不是「记 tie 然后交付」，而是「该维度无法裁决，M2-c 不能出终稿」（PRD P0-13） |
| **`noise.json` 必须含每轮原始值** | 只给离散度无法验算 |

### 6.4 负控

| ID | 注入 | 期望 |
|---|---|---|
| **NC-N-1** | `noise.json` 里删掉某统计量的 `round1` 原始值 | 报告校验器**拒绝出终稿** |
| **NC-N-2** | 用不同 `SyncInterval` 的两轮算 N | 校验器必须检出 `syncInterval` 不一致并**拒绝** |
| **NC-N-3** | 把 N 手工改成 0 | 所有 `Δ > 0` 都会判「可区分」，报告校验器必须检出「N=0 而轮间原始值非 0」的**自相矛盾** |

## §7 blocked 三锁的落地判据（P0-8）

| 锁 | 落地位置 | 判据 | 负控 |
|---|---|---|---|
| **数据锁** | 采集器 JSONL schema | blocked 维度**不得有任何数值字段**（`value`/`p50`/`p95` 一律 `null`） | **NC-B-1**：给 B2 填一个 `p50=12.0` → 校验器拒绝 |
| **计分锁** | 报告计算脚本 | 覆盖率**永远显示 `80/100`**，不归一化到 100；blocked 权重（B2 10 + B3 10）不从分母剔除也不摊给 A 类 | **NC-B-2**：把覆盖率算成 100% → 校验器拒绝 |
| **声明锁** | 报告模板 | 必须**逐字**包含 PRD 那句声明（见下），缺字即无效裁决 | **NC-B-3**：删掉声明句 → 校验器拒绝 |

**声明锁原文（字符串精确匹配，不得改一字）**：
> 「在 B 类 blocked 维度（DisplayLatency / 异 DPI 双屏连续拖拽 / 真实中文 IME 候选框定位）上，本机无法区分两条通路，因此本裁决仅基于 A 类维度。」
