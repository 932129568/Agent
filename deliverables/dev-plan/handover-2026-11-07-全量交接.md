## 1. 项目是什么

Harbor（GLM-Chat v1.0.0）——Windows 桌面 AI Agent 应用。**Electron 生产链**（R54 实测确认生产走 Electron）：

```
Electron main（harbor:// 协议 + code cache）
  └─ fastify Node server（server/src/）
       ├─ registry.js  —— js_api 方法注册表（~157 方法，与 Python 对称）
       ├─ services/pybridge.js —— R55 新建：Python 专属方法 Node 补建（11 方法）
       └─ 前端 harbor.html（单文件 115 IIFE 模块 + libs 外链）
pywebview Python 链（backend/api.py 61 js_api 方法）—— fallback / 桌面专属语义
```

**双链对称契约**：Python `ok()/err()` IPC 协议逐字节锁定（test_api_contract）；
`contract-signatures` 157 方法对称；`INTENTIONAL_DELTAS` 白名单透传防抹。

## 5. 架构关键点（新会话必读）

### 5.1 工具调用全链路（R56 优化对象）

```
tools_schema.py build()  →  34 工具 8.9KB（full_role；chat_role 0；MCP >25 折叠 9.2KB）
  → router.js routeTools()   按任务关键词裁剪工具面（域匹配+bypass 正则）
  → LLM tool_calls → sse-parser.js → model-executor.js executeBatch
  → guard.js agentGuardCheck()  guard_check HTTP →（高危）确认弹窗 → token
  → tool-executor.js executeTool()  按 name 分发 → Node 桥 / Python api.py
  → toolValidateResult() → truncateOutput → provenance 包裹 → 注入 messages
```

R56 开工前已实测的链路事实：
- 每轮 beforeRound 重建 `loadBackendTools`（HTTP 调 build_tools，无缓存）；
- 每个工具调用 ≥2 次 HTTP 往返（guard_check + execute），高危确认档 4 次；
- **读工具并行**（Promise.all），写工具按 `WRITE_SEQ_TOOLS` 在**单 run 批内**串行；
- schema 描述 ~3K token/轮 常驻开销（三段式规范已 lint 锁定）。

### 5.2 记忆系统（三写者共库）

- `memory.db`（SQLite **WAL**）：Python `agent_memory`（写者①，唯一全量语义）+ Node `pybridge.js`（写者②，@libsql/client 直读直写，DDL 幂等对齐）。
- `memory.json`：legacy 双源之一，检索打分合并。
- 检索打分：bigram 相关 × 频率强化 1.5x × 时间衰减（≤7d 1.5x / >30d 0.3x）。

## 7. 新需求：多模型并发调用同一工具（R56 范围）

**场景**：Harbor 支持并行会话（P0-3 已做 per-sid 隔离）。多个会话/模型的 agent 循环
**同时**调用同一个工具时，当前实现存在以下已识别风险面（按工具族）：

| 风险点 | 现状 | 风险 |
|---|---|---|
| 跨会话写文件 | `WRITE_SEQ_TOOLS` 串行仅限**单 run 批内**；R38-N4 路径锁作用域待复核 | 两会话同时写同一文件 → 交错/覆盖损坏 |
| memory.db 双写者 | Python 写者① + Node pybridge 写者②（WAL） | 跨进程并发写 → SQLITE_BUSY；未设 busy_timeout |
| browser 会话池 | 上限 3 **全局共享**，满时驱逐最旧空闲 | 会话 A 活跃驱动被会话 B 的导航挤占/驱逐 |
| guard confirm token | token 与确认弹窗流的生命周期 | 两会话同时弹确认 → token 归属混淆（需核验 sid 绑定） |
| sandbox 进程 | software_call 沙箱，F3c-6 进程池化留档未做 | 并发 software_call 抢占/排队行为未定义 |
| toolcache / search cache | R50 已共享单例 | JS 单线程无竞态，但跨会话缓存污染语义未定义 |

**建议方案方向**（R56 实现时裁决）：
1. per-tool/per-path 互斥锁表（跨 run、跨会话），写工具先取锁；
2. memory.db 两侧均设 `busy_timeout` + 写重试（WAL 允许单写多读，双写者需排队）；
3. browser 池按 sid 配额（如每会话最多 1-2）+ 活跃会话不可驱逐；
4. guard token 强绑 runSid，executeTool 校验 token.sid === run.sid；
5. sandbox 进程池（F3c-6 留档方案的落地窗口）。
