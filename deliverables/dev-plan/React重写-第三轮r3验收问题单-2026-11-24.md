## 二、失败项的精确归因

判据（`tests/e2e-r3-regression.mjs:535-540`）六条并列：

| 判据 | 阈值 | 实测 | 结果 |
|---|---|---|---|
| 采样帧数 | ≥ 20 | 120 | ✅ |
| 峰值位移 | 3.2 – 6.5px | **4.81px** | ✅ |
| **最小缩放** | **< 0.996** | **0.9996** | ❌ |
| 撞击边 | `left` | `left` | ✅ |
| 过冲次数 | ≤ 2 | 2 | ✅ |
| 收敛时间 | ≤ 450ms | 254ms | ✅ |
| 残余位移 | < 0.5（另一条用例） | 0 | ✅ |

**结论：只差"缩放"这一项。** 位移、收敛、过冲、残余、高光边全部达标——
也就是说用户上一轮说的"撞击不明显"，**位移维度已经修好了（2.2px → 4.81px，翻倍）**，
但设计规格要求的"协同 scale(0.988)"没有真正落到渲染上：

- 设计意图写在 `src/platform/kinetic.js:4`：「峰值位移 4.5–6.0px，**协同 scale(0.988)** 与微扭矩 0.35deg」；
- 参数也确实给了：`maxSc = 0.015`（即最陡可到 0.985）；
- 渲染串也拼了 scale：`kinetic.js:131-134` 的 `translate3d(...) rotate(...) scale(1 + softClamp(b.sc, b.maxSc))`；
- **但实测 minScale 只有 0.9996**（≈ 0.04% 收缩，肉眼不可见）⇒ 说明 `b.sc` 几乎没被激励。

**下一步排查方向（未做）**：查强撞击这条路径传入的 `vsc` 是否被覆盖成 0
（`kinetic.js:78` 默认 `vsc = -0.34`，若调用方显式传 `vsc: 0` 或传了不含 vsc 的对象，就会被压平）；
以及 `softClamp(b.sc, b.maxSc)` 的符号方向是否让 scale 被夹在 1 附近。

> **注意**：这条不能靠"调大 maxSc"糊过去。若 `b.sc` 本身是 0，调大上限也不会变。
> 必须先证明 `b.sc` 在动画期间非零，再谈幅度。

## 三、我在覆盖过程中动过的一处（已修，需明示）

**`src/shell/OverlayRoot.css` 的 `.ov-toast`：`pointer-events: auto` → `none`**

原因：跑 e2e 时 Suite-A 卡死——一条 info toast（「当前议题识别为「视频制作 (video)」，名册中暂无声明该能力的角色…」）
悬在右下，**正好盖住群聊的「■ 中止」按钮**，Playwright 报 `subtree intercepts pointer events` 并超时。

这不只是测试问题：**那一刻真实用户也点不到中止**。
而 `.ov-toast` 的内容是纯文本 `<div>{message}</div>`（`OverlayRoot.jsx:71`），**没有任何可点元素**，
所以 `pointer-events: auto` 纯属有害。容器 `.ov-toasts` 本来就是 `none`，改这一条后两者一致。

改后重跑：**Suite-A 四条全过**（这条正是解锁 Suite-A 的关键）。
