# Harbor 第二轮增量 PRD：架构收敛、可测性能与完整 UI Redesign

- 日期：2026-10-26
- 状态：待架构评审；本轮只制定增量需求，不改代码
- Language：中文
- Project Name：`harbor_v19_performance_ui_redesign`
- 技术栈：沿用 Python stdlib + pywebview + 单文件 HTML/CSS/JavaScript；不引入新框架或新依赖
- 原始需求：在现有 Harbor 上梳理整体架构并受控重构，优化关键链路延迟与运行效果，逐项验证功能及异常路径，全面 redesign UI，并完成全覆盖回归、构建、打包和如实披露。

## 1. 产品定义

### 1.1 Product Goals

1. **可维护且不破坏兼容性**：明确模块职责、状态所有权和关键数据流，只收敛已证实的高耦合点，公开 API、配置及持久化格式保持兼容。
2. **以测量驱动低延迟**：建立可复现基线，定位资源加载、启动、渲染和交互热点，以同条件前后对照证明优化结果，不作无基线性能承诺。
3. **完整、可用、可验收的工作台**：在统一工业实用视觉下覆盖所有页面、弹层与状态，逐项走通功能入口和异常路径，并明确自动化、真机与外部端点的覆盖边界。

### 1.2 User Stories

- 作为日常对话用户，我希望流式生成、停止、重生成和切换会话保持及时且无串写，以便连续完成任务。
- 作为 Agent 用户，我希望工作区、工具权限、Guard、计划与检查点的状态和结果清晰可见，以便安全地授权与追溯操作。
- 作为配置与运维用户，我希望模型端点、本地模型、MCP、沙箱、WebDAV、更新及审计入口完整可达，失败时有可行动的反馈，以便独立排查问题。
- 作为长时间使用者，我希望高密度信息在浅色、深色、不同窗口尺寸和 reduced-motion 下仍清晰稳定，以便低成本阅读和操作。
- 作为维护者与 QA，我希望有架构图、性能原始记录、功能矩阵和构建证据，以便判断每次改动是否有效且可回滚。

## 3. 范围与优先级原则

- **P0 / Must**：兼容与数据安全、架构和性能事实、核心链路、全部 UI 主路径、完整自动回归及证据披露。
- **P1 / Should**：测量证实后的进一步优化、可访问性和异常路径补强、可复用测量脚本及报告易读性。
- **P2 / Could**：不改变契约的代码与视觉债务清理；仅在 P0/P1 全绿且证据充分时进行。
- 重构不按文件行数机械拆分；没有调用方、重复状态、重复 I/O 或实测热点证据，不做大规模搬移。

## 5. UI 设计规范

### 5.1 色彩与材质

- **主色/唯一品牌强调色：工业青蓝**。浅色建议 `#0E7490`，hover/pressed 使用同色相深阶；深色建议 `#22D3EE`，需按实际背景校准对比度。
- **中性色**：浅色以石墨文字 + 冷灰工作面，深色以近黑灰工作面 + 分层灰面板；避免大面积纯蓝渐变、彩色玻璃卡片和多彩 KPI。
- **语义色独立**：成功绿、警告琥珀、错误红只表达状态，不作为第二品牌强调色；所有状态同时配文字或图标。
- 用 1px 分隔线和小面积表面层级替代层层浮卡；圆角以 4–8px 为主，保留契约类名与变量名。

### 5.2 字体与数字

- 正文首选 **思源黑体 / Source Han Sans SC**，其后使用 `Microsoft YaHei`、`PingFang SC`、通用 `sans-serif` 回退；正文不得使用 Inter、Roboto、Arial 或 `system-ui`。
- 数字、token、费用、时间戳、路径及代码首选 **JetBrains Mono**，其后使用 `Cascadia Code`、`Consolas`、通用 `monospace`；关键数值使用 `tabular-nums`。
- 不新增在线字体请求。若本机没有首选字体，按回退链验收；是否随包内置字体须另行评估许可、体积和打包影响。

### 5.3 阴影与动效预算

- 阴影只用于真实层级：下拉、浮层、模态可使用一层低透明度环境阴影；普通列表、输入框、消息正文和每个设置块不叠阴影。
- 去除持续极光漂移、扫光、呼吸、无意义数字滚动和大面积 blur 的默认必要性；装饰不得抢占流式与工具执行状态的注意力。
- 微交互只动 `transform` / `opacity` / 颜色，建议 90–160ms；面板/模态建议 160–220ms；不新增无限循环装饰动画，不用弹簧过冲表达工业界面。
- `prefers-reduced-motion: reduce` 与 `fx-off` 下停止装饰、平滑滚动、 stagger 和循环动画；功能状态以静态文本/图标保留，不能只把速度调快后仍反复闪烁。

### 5.4 布局草案

- 左侧保留紧凑 rail；会话上下文与主工作区明确分区，隐藏的旧 `mainNav` 仅为契约保留，不恢复双重可视导航。
- 对话页优先消息和输入，工作区/权限为辅助状态；会话页强化扫描效率；分析页采用对齐的仪表与图表；设置保持左分组右内容但减少卡片套卡片。
- 工作区与 Guard 分段保留；危险项、永久信任和沙箱边界在视觉上有明确警告，不仅靠颜色。
- 所有浮层统一边界、焦点、层级和窄窗策略，禁止 tooltip/popover 被父容器裁切。

- 优化项需有热点证据和前后对照。若差异落入噪声或样本不足，结论为“未证实提升”，不是“已优化”。
- 无绝对毫秒硬指标时不设虚构目标；基线后新增预算必须记录依据并由架构师/QA 确认。
- 真机启动/渲染性能因禁止主动启动 exe，除非用户提供足够复验数据，否则保持“未覆盖”。

### 6.3 UI、响应式与功能验收

- 按 D2 全组件清单检查浅色/深色、默认/空/加载/错误/禁用及 reduced-motion；保存截图或静态/浏览器证据。
- 按 D4 尺寸与缩放矩阵检查无横向页面溢出、遮挡、裁切、不可达按钮和异常双滚动；聊天代码/表格自身可滚动不算页面溢出。
- 仅键盘完成新建/发送/停止/切换会话/打开设置/修改并保存/关闭弹层；焦点可见且关闭后返回触发入口。
- C1 功能矩阵逐行关联自动测试或人工步骤；模拟测试、受控页面、真实端点、新版 exe 真机四者分列。
- 由用户打开新版 exe 后，至少复验对话、会话、分析、工作区、设置和通知，以及流式/停止/切换/重生成；未收到截图前新版真机结论为待复验。

## 7. 执行 Wave 与交付物

1. **Wave 0：保护现场与事实**：记录 status/diff、架构清单、功能矩阵、性能协议和基线；不得修改或清理现有 26 个 tracked 修改及未跟踪文件。
2. **Wave 1：架构小步收敛**：每次只处理一个有证据的问题，跑最小回归与契约，再进入下一项。
3. **Wave 2：热点优化**：一次只改一个主要变量，保存前后样本；无收益或出现正确性回退即撤回该 Wave 的增量。
4. **Wave 3：完整 UI**：先 token/控件，再页面/弹层，再响应式与可访问性；每批重建并跑 UI 契约。
5. **Wave 4：独立 QA 与打包**：全量测试、性能复核、安装器与三 exe、覆盖缺口及用户复验清单。

交付至少包括：架构与数据流图、模块职责表、功能覆盖矩阵、性能协议/原始样本/对照报告、UI 规格与截图矩阵、全量 QA 和打包报告、风险与未覆盖清单。

## 8. Out of Scope

- 新产品功能、新前端/后端框架、新运行时依赖。
- 公开 js_api 契约、`get_api_info`、`API_VERSION`、公开 config 或任何持久化格式变更。
- macOS 专项适配与验收、代码签名、发布/推送。
- 主动启动 `dist/Harbor.exe`；自动化黑/白屏截图直接定性产品 Bug。
- 使用真实账号凭据进行破坏性操作，或把 CAPTCHA 绕过纳入能力。
- 无测量证据的“提升 xx%”“毫秒级”“最佳/零延迟/全面流畅”等绝对性能承诺。

## 9. 风险与回滚

| 风险 | 控制与回滚 |
|---|---|
| 覆盖用户现有未提交工作 | 全程只增量编辑；Wave 前记录 diff/哈希；禁止 reset --hard、checkout 覆盖、整目录还原和删除未知文件。 |
| 重构破坏 API/配置/数据 | 契约和数据兼容测试先行；失败只回退当前 Wave 的最小增量，不退回上轮全部修复。 |
| 前端拼接顺序或晚桥回归 | 保持模块顺序，启动/晚桥专项测试；失败恢复当批模块与模板增量并重建。 |
| 性能优化牺牲正确性 | 每热点单独对照；流式、取消、权限、回滚测试任一失败即停止合入并回退该实验。 |
| 全面换肤违反 UI 契约 | 契约 DOM/onclick/callApi/类/变量只增不改；隐藏兼容节点不删除；每批跑 UI 契约与截图检查。 |
| 视觉特效造成 GPU/重绘回退 | 以 profile 决定阴影/blur/动画；保留 reduced-motion/fx-off；退化时优先移除装饰而非功能反馈。 |
| 构建或打包污染证据 | 保存当次源码哈希、构建日志与三 exe 哈希；新产物单独验证，不删除或覆盖旧证据。 |
| 把未覆盖当真机通过 | 报告分列自动、受控人工、真实端点和用户 exe 复验；缺口显式保留，不用推断补绿。 |
