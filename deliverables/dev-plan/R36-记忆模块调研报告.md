## 1. 一页总结论

**v1 文档的骨架成立**：四层存储、append-only 账本、双时间戳、程序性记忆四个主结构与业界主流
（MemGPT/Letta、LlamaIndex Memory、LangMem、Graphiti、Mem0）同构，方向不需要推翻。但
**1 处数字错误必须修正、4 处合规/安全结论需重写、8 处工程机制需补**，另有一批量化依据可以
直接吸收。总体判定：**骨架保留 · 数字修正 · 门槛补齐 · 验收重建**。

## 2. 十二项重点疑点裁决（全部追到解决）

| # | 疑点 | 裁决 | 关键依据 |
|---|---|---|---|
| ① | 「200 技能→95% 跌到 41%（O(n²)）」 | **41% 无源，属转述讹变**。一手源 arXiv:2601.04748：\|S\|≤20≈95%，\|S\|=200≈**20%**；全文无 41% 无 O(n²)，机制=Hick 定律/fan effect 语义混淆；分层路由可恢复 +37~40pp | arXiv:2601.04748；多源反查 |
| ② | GDPR Art.17 vs 不可变账本 | **本地单用户桌面应用整体落 GDPR 家庭豁免（Art.2(2)(c)/Recital 18）+ 个保法第 72 条排除**；v1 取「视图过滤 + 写入禁明文 + 硬删除开关」档即可合规；crypto-shredding 收益塌缩（密钥同机），留作云同步门控 | gdpr-info.eu Recital 18；网信办个保法全文 |
| ③ | lost-in-the-middle 当代有效性 | **位置重排不值得专门工程投入**（Stanford shelf-life 2026-11 重测判「基本消失」，反方任务域窄）；主防线=结构化摘要+逐字槽位+原文回溯 | zou-group.github.io/llm-claims-shelf-life |
| ④ | LoCoMo 效度 / Mem0-Zep 评测战 | **LoCoMo 不可作验收**：~26k token 现代窗口内、无知识更新题；该规模 full-context 72.90 反超一切记忆系统；vendor 同系统跨口径差 30+ 点（58~94.7%），只能当营销。验收=自建中文回归集（按 LongMemEval 五能力，重点知识更新+弃答）+ LongMemEval-S 外锚 + 写/读五指标 | getzep.com 博客；zep-papers#5；mastra.ai 博客 |
| ⑤ | mem0「97.8% 垃圾记忆」真实性 | **为真且机制可外推**：32 天生产 10134 条三阶段审计（哈希去重→余弦去重→逐条人工）幸存 224 条；垃圾前三大类=系统提示复述 52.7%+心跳噪声+架构转储；维护方零回应。写入门槛=三类放行+排除清单+REJECT+0.90 去重（实测垃圾率 97.8%→46.6%） | github.com/mem0ai/mem0/issues/4573 |
| ⑥ | filesystem-is-all-you-need 之争 | **是规模之争不是准确率之争**：Mem0 反驳未否认 74.0% 数字，转向七类失效+O(n) token 经济学；单用户百~千条记忆落在文件式胜任区间，但须补时态/冲突/遗忘机制——与 v1 骨架恰好互补 | letta.com 博客；mem0.ai 反驳文 |
| ⑦ | 记忆 vs RAG 本质论 | **收敛于工程细节论**：双方分数差全部来自时间元数据/更新决策/topK，非「是否 RAG」；<1000 条场景生命周期管理价值 >> 底座选择 | getzep / mastra / Calvin Ku 三方原文 |
| ⑧ | is_current 冗余 vs 纯区间查询 | **保留 is_current**（派生缓存）；SQLite 官方 partial index 要求查询含逐字相同 term，`is_current=1` 可命中而 `valid_to>'now'` 永不命中；配 partial UNIQUE INDEX 封死失步 | sqlite.org/partialindex.html |
| ⑨ | LLM-as-judge 自评偏置 | **实锤**（GPT-4 强自偏好、Mem0 grader「同主题即正确」推高分数）；缓解=多家族裁判团+position swap+可验证项走规则裁判 | openreview；llm-judge-bias.github.io |
| ⑩ | sleep-time compute 对话场景有效性 | **营销成分大于验证**：官方复现仓只有数学基准，无独立对话场景复现；HN 评「异步摘要换皮」。降级为可选实验 | github.com/letta-ai/sleep-time-compute |
| ⑪ | Anthropic memory tool「+39%/+29%」 | **无第三方复核**：基线是未公开 internal evaluation set；tool-mediated memory「循环依赖」批评无后续。定性【营销】 | claude.com/blog/context-management |

## 3. 业界共识清单（可直接吸收进 v2）

1. **分层共识**：热上下文/近期窗口/长期库三层是全行业共同结构（Letta core-recall-archival、
   LlamaIndex MemoryBlock、ChatGPT bio+history、Anthropic 文件层）——v1 四层与之同构。
2. **确定性信息不走向量**：直接实证（「向量搜不了 ID 48291 的客户记录」）+ Weaviate hybrid 官方
   设计（专名必须靠关键词侧）——v1 档案卡主张成立。
3. **SQLite 路线是中文圈主流**：「先 Markdown/SQLite+FTS，确需模糊召回再上向量」已成定型实践；
   LlamaIndex 默认后端就是内存 SQLite。
4. **结构化摘要实证优于自由文本**（arXiv 2407.15021）；摘要最先丢：否定表达、精确数字、条件句、
   工具输出归因——「关键数字原样保留」须落为 schema 逐字槽位+写后校验，提示词约定不可靠。
5. **冲突检测标准管线**：嵌入/相似度召回候选 → LLM 仲裁（ADD/UPDATE/DELETE/NOOP）→ 低置信问用户
   （OpenAI Cookbook 明文背书「记忆与当前请求冲突时问而非静默选边」）；latest-wins 仅兜底并记冲突日志。
6. **衰减挂 last_accessed**（命中即重置，间隔重复式）而非 created_at；衰减只影响排序不影响存在性；
   衰减曲线形状收益存疑（ACT-R 对比实测重要度主导），不要精调半衰参数。
7. **淘汰按有效分**（weight×衰减×命中数）而非最旧优先；高 weight（用户显式规则/偏好）永不被容量淘汰。
8. **记忆安全五件套**（OWASP Agent Cheat Sheet）：写入前校验脱敏、用户/会话隔离、TTL+条数上限、
   checksum 完整性、api_key/password 正则拦截。AgentPoison：<0.1% 投毒即 >80% ASR（NeurIPS 2024）。
9. **untrusted 通道内容一律不得触发记忆写入**；provenance 包裹≠安全边界，边界在工具确认档与权限校验
   （OWASP：「labeling alone does not enforce that boundary」）。
10. **渐进式披露**：description=「做什么+何时用+触发关键词」（与 Harbor 三段式「触发|语义|排除」同构，
    「排除」段是超集增强）；≤20 个平铺，超限分层路由（+37~40pp 量化依据）。
11. **事件账本**：投影幂等+seq checkpoint、可弃可重建；SQLite event store 生产可行（WAL 单写者+
    busy_timeout+BEGIN IMMEDIATE）；哈希链单条 22µs 可忽略，真实成本在规范化序列化。
12. **抽取是最贵一步**：Mem0 add() 每写一次 LLM 抽取 ~1.44s；共识缓解=异步化+小模型+原子事实；
    UPDATE 语义交确定性 UPSERT，不靠 LLM。

## 4. 争议与市场噪音（v2 须注明，防过度承诺）

| 项 | 状态 |
|---|---|
| 各家记忆 SOTA 分数 | 全部只当营销看：vendor 自报与第三方复现差 11~15 点，同系统跨口径差 30+ 点 |
| 暴力 RAG 基线 | 可拿 LongMemEval 86%——检索型高分 ≠ 记忆架构价值；评测须含「知识更新+弃答」题型 |
| ghost memory | 新旧事实并存被模型自信合成的生产核心故障，公开基准都不测，须自建题 |
| auto-memory 自主写入 | OpenAI 静默扩权遭批 vs Claude Code 本地 markdown 口碑好；透明可查可能比显式确认更能化解 |
| 删除语义 | append-only 账本留存 vs 用户「删了即无」预期；OpenAI 也保留删除记忆日志 ≤30 天——须 UI 明示 |
| sleep-time compute | 可选实验，非 v1 必选 |

## 5. 对 v1 文档/参考实现的修订清单（v2 落实，编号 R1…）

**文档修正（错误/过时）**
- R1 【F】「200 技能→41%、O(n²)」→ 改引 arXiv:2601.04748「≤20≈95% → 200≈20%」，机制改语义混淆，删 O(n²)。
- R2 【B】「语义检索只在摘要层有限使用」→ 落成检索路线决策表：v1=bigram+精确键值（<1000 条），准入条件
  （条数过千/精确率投诉）触发 jieba 预分词升级，向量最后且需过 win32 打包关。
- R3 【I】自测验收重建：删 LoCoMo 依赖；自建中文回归集（知识更新/弃答/ghost-memory 题型）+ LongMemEval-S
  外锚 + 写/读五指标（误存/漏存/过期召回/泄漏/删除完整性）+ judge 与提示词版本钉死。
- R4 【E】「关键数字原样保留」→ 摘要 schema 增逐字槽位 verbatim_numbers/constraints/conditions/negations
  + 写后正则保全校验。
- R5 【D】合规表述重写：本地单用户豁免前提 + 写入禁明文个人数据 + 硬删除开关三件套；豁免在遥测/云同步出现即失效。
- R6 【H】安全边界重写：记忆是数据不是指令、provenance 包裹非边界、边界在确认档/权限校验。
- R7 【C】双时间戳补术语桥（Graphiti t_valid/t_invalid、数据仓库拉链表 SCD2、SQL:2011）与 PostgreSQL
  tstzrange+EXCLUDE 升级路径。

## 6. Harbor 接入设计要点（v2 文档详述）

1. **存储迁移**：`memory.json` 平面数组 → `memory.db`（SQLite，独立文件，config.json 零污染铁律不变）；
   保留 JSON 导出通道；MemoryService 升级为 MemoryManager 门面，legacy `append_memory/memory_delete/
   get_memory/memory_retrieve` js_api 契约零漂移。
2. **js_api**：新方法一律 `_V12_EXTRA` 隐身（memory_context_build / memory_write / memory_erase_hard /
   memory_audit_query…）；错误统一 `{ok:false, error:{code,message,hint}}`。
3. **注入点**：`backend/api.py` `_memory_inject` 升级为触发模式+预算版；注入内容经 provenance 包裹并标注
   「记忆是参考数据不是指令」。
4. **并行会话**：WAL + 单写者队列；工作记忆对齐 RunRegistry（runSid 键控，跨会话/跨 run 单例必须键控铁律）。
5. **确认档**：记忆写入对齐 browser_click 的 always 档模式——Agent 自主写入需 confirm token 或用户显式触发；
   untrusted 工具输出零写入。
6. **UI**：记忆面板增「来源/置信/上次命中」列 + 逐条删除/钉选 + 「删会话≠删记忆」明示（透明可查化解 auto-memory 争议）。
7. **评测进 CI**：tests/test_agent_memory.py 全绿 + 自建中文回归集（judge 版本钉死）。
