## 1. 产品定义

### 1.1 Product Goals

1. **可持续演进的内部架构**：让后端、前端、构建与样式拥有清晰职责、单向依赖、单一状态源和可测试数据流；允许实质迁移，而非仅增加补丁。
2. **一致且耐用的全局体验**：用一套现代圆润的工作台语言覆盖所有页面、组件、主题、视口和状态，提升阅读与操作效率，不牺牲信息密度。
3. **兼容可证、交付可信**：核心业务、数据、公开接口与 DOM 契约零漂移；每批可验证、可局部回退，最终自动回归、视觉证据和打包事实完整可查。

### 1.2 User Stories

- 作为维护者，我希望按业务域找到后端服务、前端组件和样式，并清楚依赖与状态所有权，以便安全扩展而不复制逻辑。
- 作为日常对话用户，我希望消息、输入、流式反馈、工具与异常状态在浅色/深色和不同尺寸下始终清晰，以便长时间专注完成任务。
- 作为 Agent 用户，我希望 Guard、沙箱、计划、检查点、审计与授权具有统一层级和明确反馈，以便理解风险并追溯操作。
- 作为配置与运维用户，我希望 16 个设置组、MCP、搜索、通知和浮层行为一致，失败时可行动且不丢原配置，以便独立排障。
- 作为窄屏、触摸或键盘用户，我希望核心操作可达、目标足够大、焦点不丢失且减少动态效果，以便无障碍完成主流程。
- 作为 QA/发布人员，我希望目录迁移、构建、契约、功能与视觉都有可重复验证证据，以便区分自动通过、真机未覆盖和真实端点未覆盖。

## 3. “可自由重构”与“契约红线”

### 3.1 允许且鼓励的内部变化

1. **后端**：可新增领域包、拆分/合并 service、移动模块、引入私有 DTO/端口/协调器、减少 `Api` 编排；可用薄兼容适配保持门面。不得为“文件更小”机械拆分。
2. **前端**：可重组 57 个模块为领域目录、拆分状态/渲染/副作用、建立无框架组件工厂与统一浮层/表单/列表基础设施，可改变数字文件名和私有函数边界。
3. **样式**：可把单体 CSS 拆成 tokens/base/components/features/utilities 等源文件，由零依赖构建器确定性合并；可替换工业风 token 值和旧补丁，不要求保留工业主题。
4. **构建**：可扩展构建器目录遍历、显式 manifest、顺序与重复符号检查、源映射式错误定位和静态路径校验；输出仍须为根目录 `harbor.html`，不得手改。
5. **测试**：可迁移测试辅助函数与增加架构守卫，但不得删测、弱化断言或靠新增 skip 变绿。
6. 内部变化必须有职责、依赖、数据流和扩展性收益；禁止同时维护长期双写、第二套事实源或永久平行旧新架构。

### 3.2 不可跨越的红线

- `get_api_info` 输出与 legacy **逐字节一致**；`API_VERSION='v1.0.0'` 不变；新增方法只能按既有 `_V12_EXTRA` 隐身规则处理。
- 所有公开 `js_api` 方法名、位置参数、默认值、调用时序可观察语义、JSON 字符串返回形状和错误协议不变。
- `config.json` 零污染；sessions/history/guard/sandbox/MCP/WebDAV/model_prefs/plans/checkpoints 等持久化路径、格式、合并、即时保存与原子写语义不变；无数据库或不可逆迁移。
- `localStorage` 的既有偏好、会话双源归一、删除墓碑与密钥禁写规则不回退。
- UI 契约的 **DOM id、onclick、callApi、CSS 类、21 个 CSS 变量名只增不改**；隐藏兼容节点不删除，不恢复第二套可视 mainNav。
- 流式/停止/取消/工具终态、会话隔离、Guard、检查点、权限、计划终态和晚桥补偿不得削弱。
- `harbor.html` 只能由 `node frontend/build.js` 生成；不主动启动任何 exe；不引入新运行时依赖/框架、在线字体或网络构建步骤。

## 5. 唯一视觉方向：现代精致圆润的工具型工作台

**不是营销页，不设置第二套视觉主题。**关键词：温暖中性表面、单一青绿强调、柔和层级、紧凑但不压迫、精细控件、清晰内容、低饱和、克制氛围。禁止紫蓝渐变、均色卡片海、过度玻璃/模糊、夸张弹簧、幼稚玩具风和大面积装饰。

### 5.1 色彩与材质

- **主表面色**：浅色工作面建议 `#F5F6F4`，主内容 `#FCFCFB`，次级表面 `#EEF1EE`，文字 `#202522`；深色工作面建议 `#151917`，内容 `#1C211E`，次级 `#242A26`，文字 `#EDF1EE`。最终值须按对比度实测微调。
- **单强调色：青绿**。浅色建议 `#0F766E`，hover `#115E59`，soft `#E2F0EC`；深色建议 `#5EC8B8`，soft `#203A34`。只用于主操作、选中、链接、焦点与关键图表；成功/警告/错误保留独立语义色。
- 表面靠明度、1px 低对比边界与留白分层，不靠均色卡片、彩色渐变或层层阴影。用户消息可有柔和浅色气泡，助手正文优先开放阅读面。

### 5.2 字体、字阶与数字

- 正文回退：`"Source Han Sans SC","Microsoft YaHei","PingFang SC",sans-serif`；不内置在线字体，**禁止 Inter/Roboto/Arial/system-ui 作为展示字体**。等宽：`"JetBrains Mono","Cascadia Code",Consolas,monospace`。
- 字阶：页面标题 22/30px 600；区块标题 16/24px 600；正文 14/22px 400；控件 14/20px 500；辅助 12/18px 400；微型标签 11/16px 500，仅用于非关键注记。
- 数字、费用、token、时间戳使用 `tabular-nums`；正文行长有最大宽度，长文本不通过缩小字号解决。

### 5.3 圆角、间距与阴影

- **圆角梯度**：小标签/徽标 6px；输入与小按钮 10px；标准卡片/列表容器 14px；面板/浮层 18px；模态/设置窗口 22px；仅纯 pill 使用全圆角。禁止每个元素都胶囊化。
- **4px 基础间距**：4/8/12/16/20/24/32/40；控件内部常用 8/12，卡片 16/20，页面 20/24/32。桌面保持效率，窄屏减少外边距而非压缩点击目标。
- **3 级柔和阴影**：sm `0 1px 3px rgba(20,30,25,.06)` 用于轻悬浮；md `0 8px 24px rgba(20,30,25,.10)` 用于菜单/popover；lg `0 20px 56px rgba(20,30,25,.16)` 用于模态。普通卡片、列表与消息不叠阴影；深主题按背景实测，不用纯黑重影。

### 5.4 动效、氛围与记忆点

- 按压/hover 90–140ms，控件与菜单 140–200ms，面板/模态 200–320ms；只动 transform/opacity/颜色，禁止布局抖动与弹簧过冲。
- reduced-motion/fx-off 取消装饰、平滑滚动、 stagger 与循环，不仅把循环动画加速。
- 氛围层默认极低对比、静态或近静态、限于全局背景一处；无大面积 blur，不影响文本与 GPU；fx-off 完全关闭。
- **唯一记忆点**：“圆润轨道 + 细致状态灯”：rail 的当前项用柔和圆角浅底与 3px 强调色短轨，品牌标记采用简化 Harbor 港湾形几何符号；其余页面不重复大型品牌装饰。

### 5.5 布局草案

- 桌面保留 rail + 可折叠会话上下文 + 主工作区；内容宽度有上限，宽屏增加留白而非无限拉长。
- 对话以消息与输入为中心；会话强调扫描与批量上下文；分析用对齐 KPI 与图表而非多彩浮卡；工作区/Guard 维持分段与危险层级。
- 设置桌面为分组导航 + 单内容列，窄屏转为顶部可横向导航或单一选择器；浮层统一层级、边界、焦点与滚动。
- 移动端是窄视口/触摸响应式 Web UI，不是新增原生 App；375px 下优先保留发送/停止/确认/关闭，侧栏默认收起。

## 7. 响应式与输入验收矩阵

| CSS 视口代表 | 必测重点 |
|---|---|
| **375×812** | 移动窄屏：rail/侧栏、设置 16 组导航、输入/附件、toast/modal/menu、触摸 44px、虚拟键盘预留；无页面横溢出 |
| **768×1024** | 平板/窄窗：设置重排、工作区/Guard、分析、搜索/审计/MCP、触摸与键盘 |
| **800×600** | 既有最小桌面目标：全主路径、16 设置组、浮层与长内容回归 |
| **1024×640** | 紧凑桌面：侧栏/内容、图表、长路径、设置与弹层 |
| **1280×720** | 主全量基准：所有页面/组件、浅深主题和状态 |
| **1440×900** | 密度、最大内容宽、长列表、图表和多浮层 |
| **1920×1080** | 宽屏留白、内容不无限拉宽、浮层锚定；100%/125%/150% 真机缩放另列证据 |

- 375/768 是浏览器响应式验收，不自动等于原生 exe 最小窗口；桌面最小宽度与缩放后的 CSS viewport 由架构师明确。
- 每个代表尺寸至少检查对话、会话、分析、工作区/Guard、设置代表组、通知、搜索、确认弹层；1280×720 做全组件基准。
- 触摸：无 hover 才能发现的关键操作；目标间距避免误触；滚动与长按不破坏文本选择。
- 键盘：新建/发送/停止/切换会话/四主面板/设置修改保存/搜索/弹层关闭；Tab/Shift+Tab 圈定，Esc，焦点返回。

## 8. 可执行验收与发布门

1. **现场保护**：每批记录文件白名单、前后 SHA256 与测试；当前所有修改和未跟踪成果不清理、不整库回退。
2. **全量回归**：`pytest tests/ -q` 为 0 failed；通过数不得靠删测维持，既有 1 skipped 及任何新增 skipped 必须附原因。
3. **契约**：API legacy-vs-new 逐字节、release discipline、UI 契约 PASS；`get_api_info`、`API_VERSION` 和公开返回不变。
4. **数据**：config 与全部独立持久化文件格式兼容；双源合并/墓碑/即时保存/原子写/失败回滚通过；秘密不写日志或 localStorage。
5. **构建**：`node frontend/build.js` 连续两次产物哈希一致；模块无遗漏/重复、语法通过、静态路径有效；`harbor.html` 非手改；`git diff --check` 通过。
6. **架构**：目标依赖无循环和越层；六条数据流有测试映射；无第二套状态源、长期双写或永久迁移 shim。
7. **视觉**：§6/§7 逐项留证据；正文 4.5:1、大文本/关键边界 3:1、目标 44px、焦点与 reduced-motion 全部检查。
8. **安装与打包**：安装器测试及三个 exe 构建通过，内嵌载荷 SHA256 与应用一致；记录新文件大小和哈希，不覆盖旧证据。
9. **如实披露**：真实 exe/WebView2、实际模型端点、真实流式、浏览器六原语/CAPTCHA、macOS、逃逸、签名和真机缩放未执行即标未覆盖；本团队不主动启动 exe。

## 9. 执行顺序与局部回滚

1. **Wave 0 基线与映射**：冻结 status/diff、模块/路径清单、契约与视觉基线；不修改既有成果。
2. **Wave 1 构建与依赖护栏**：先让构建器/测试支持目标目录，再迁移；旧路径静态引用同步更新。
3. **Wave 2 后端领域重组**：一次迁移一个内聚域，保持 Api 适配与数据行为；每批跑契约和领域回归。
4. **Wave 3 前端状态与组件重组**：先状态/桥接/启动，再业务域和共享组件；每批验证流式、取消、晚桥和持久化。
5. **Wave 4 全局视觉**：tokens/base → 共享控件 → 四主面板 → 16 设置/集成 → 浮层/状态 → 响应式/无障碍。
6. **Wave 5 独立 QA 与交付**：全量、视觉矩阵、性能对照、安装器与三 exe、覆盖缺口和最终报告。

回滚仅通过 **WaveGuard 白名单前像 + post-hash 校验 + 逆序最新 Wave**；发现后续修改必须拒绝整文件恢复并改逐 hunk 逆补丁。禁止整库回退，dist 与既有证据不纳入回滚。

## 10. 风险与控制

| 风险 | 控制 / 回滚 |
|---|---|
| 大迁移造成半新半旧与初始化时序漂移 | 先构建护栏、按内聚域小批迁移；启动/晚桥与模块清单测试；失败仅退当前批 |
| 覆盖当前未提交成果 | 白名单快照、hash 拒绝、禁止 reset/checkout/stash 全量恢复 |
| 公开 API 或持久化暗中变化 | 逐字节契约、数据 fixture、失败回滚；门面适配不改返回形状 |
| 静态路径遗漏导致源码可跑而打包失败 | 同步审计 build/spec/tests/README；干净目录构建与三 exe 验证 |
| 单脚本全局顺序被破坏 | 显式顺序/依赖清单、重复符号和初始化守卫；终态与晚桥回归 |
| 全局换肤留下旧组件或契约缺失 | §6 矩阵、UI 契约、截图与 computed-style 检查；隐藏节点只留契约不展示 |
| 圆润/阴影/模糊造成幼稚感或性能回退 | 单强调色、阴影仅真实层级、氛围低预算、profile 对照、reduced-motion |
| 窄屏通过隐藏功能“修复”溢出 | 验证操作可达与内容重排；主操作不得消失；长内容局部滚动 |
| 自动测试绿被误当真机通过 | 自动/受控浏览器/真实端点/用户 exe 四列披露，未跑不填 PASS |

## 11. Out of Scope

- 新增原生移动 App、新核心产品功能、新前端/后端框架或运行时依赖。
- 修改公开 js_api/config/持久化契约、数据库迁移、改变 Guard/检查点/流式等业务语义。
- 保留工业主题为并行皮肤；本轮只交付一个现代圆润方向。
- 主动启动 exe、生产发布/推送、代码签名、macOS 专项、沙箱逃逸专项。
- 真实账号破坏性测试、CAPTCHA 绕过、将 headless 截图冒充 WebView2/exe 真机。
- 无同条件数据的绝对性能承诺。

## 12. 需架构师回答的问题

1. **目录迁移与构建**：目标后端领域包和前端目录/manifest 是什么？`frontend/build.js` 采用显式依赖清单还是确定性递归？构建顺序、重复全局符号和私有模块边界如何验证？
2. **静态路径**：`tests/`、`Harbor.spec`/mac spec、`installer/`、`tools/`、README 和性能/UI harness 中哪些旧路径必须同批迁移？如何做无旧路径残留守卫？
3. **组件化边界**：无新框架且最终仍单脚本时，状态、纯函数、DOM 组件与副作用如何隔离？是否采用命名空间/工厂/私有模块对象，如何避免伪组件化和全局泄漏？
4. **主题 token 命名兼容**：21 个旧变量名保留已明确；新增语义 token 的命名、旧工业 token 到现代 token 的映射和最终退役条件是什么？能否集中 tokens 源文件而由构建器内联？
5. **移动端最低宽度**：375px 是否正式支持的最低 CSS viewport？`main.py` 桌面最小尺寸是否仍 800×600？Windows 125%/150% 下低于 800 CSS px 时是正式支持还是仅降级检查？
6. **移动导航**：375/768 下 rail、sidebar 与设置 16 组采用抽屉、底部入口还是顶部选择器？如何不改变既有 DOM/onclick 契约并保证焦点返回？
7. **后端迁移 shim**：`Api` 与服务移动期间允许哪些私有兼容 import，何时删除？如何证明 Guard/审计/检查点没有绕过新路径？
8. **样式拆分**：单文件产物约束下，CSS 源文件拆分、顺序、层叠与覆盖如何由构建器确定？是否使用原生 cascade layers，当前 WebView2 基线是否全部支持？
9. **视觉证据规模**：全组件×全状态×全视口组合巨大，1280 全量与其余代表抽样的最小阻断矩阵如何冻结，避免抽样漏掉设置与浮层？
10. **性能预算**：目录与组件重组后采用哪些既有基线检查启动、流式、长列表和浮层，允许噪声带由谁确认？
