| Present p95 | 6.28317 ms | 6.26243 ms | 0.02074 | 0.00677 | **3.07** | **B 优** |
| Present p99 | 6.41633 ms | 6.38473 ms | 0.03160 | 0.02180 | **1.45** | **B 优** |
| Drop rate | 0.043% | 0.064% | 0.021pp | 0.010pp | **2.04** | **A 优** |

各通路三轮原始值：

| 统计量 | A 三轮 | B 三轮 |
|---|---|---|
| p50 | 6.0622 / 6.0603 / 6.0603 | 6.0600 / 6.0602 / 6.0608 |
| p95 | 6.2821 / 6.2843 / 6.2831 | 6.2581 / 6.2644 / 6.2648 |
| p99 | 6.4283 / 6.4065 / 6.4142 | 6.3852 / 6.3738 / 6.3952 |
| dropRate | 0.0004 / 0.0004 / 0.0005 | 0.0006 / 0.0007 / 0.0006 |

**这一维度只能说「同一量级，各有局部优势」，不能说「某一条更好」。** 理由三条：

1. **三条 decided 全是弱信号**：Δ/N 分别 3.07 / 1.45 / 2.04，都在 1~3 倍噪声区间。R-3 明令不按 Δ 大小给分，1.1N 与 10N 同分——所以「B 在 p95 上是 3 倍噪声」不等于「B 有优势」。
2. **p95/p99 的方向与 dropRate 相反**：B 尾部更窄但掉拍更多，A 掉拍更少但尾部更宽。这**不是一个矛盾**，而是两个独立维度：尾部抖动幅度 vs. 掉拍频次。
3. **差异有明确的结构解释，不是实现质量**：A 是双窗双交换链，每帧 Present 两次（实测两窗合计 submit ≈ 529µs），所以尾部更宽；但两窗各自独立等 waitable，单次超时不会连锁，所以掉拍更少。B 是单链单 Present，尾部更窄，但一次 stall 直接反映为一次掉拍。**这是「两次提交 vs 一次提交」的结构代价，不是谁写得更好。**

## §E 决策要素清单（不写进裁决结论）

1. **A 侧物理上不存在 60Hz 档**。`dcomp_demo` 的 `SyncInterval=1` 被 DWM 按物理屏 165Hz 钉住，无法降频；B 侧 `setFrameRate(60)` 是 Chromium 侧软件限帧。两者不是同一机制，故 A/B **仅在 165Hz 一档可比**（R-4 同参数）。
2. **所有 GPU 读数来自 Intel Iris Xe 核显**（运行日志 `ADAPTER_NAME` 实测）。本机虽有 RTX 4070 Laptop，但它不驱动主显示，D3D11 设备选中的是核显。**本裁决不代表 4070 的表现。**
3. **`presentP50` 无分辨力**：实测 1998 个间隔中 1996 个落在同一 vsync 档（k=1），三轮 N=1.9µs 是「被量化在同一档」的必然结果，不是仪器精确。按元规则第四条，它不作强弱结论依据。
4. **WDDM 有个天然的 ceiling**：`SyncInterval=1` 下所有读数都贴着 vsync 周期，任何两条被同一上游约束钉死的链路都会「看起来一样快」。**这正是必须用掉拍率（分辨率恰好 1 拍）而不能只看 p50 的原因。**
5. **PM 建议（不具约束力）**：`tie` 时倾向 A，理由是 A 的未测风险（跨屏拖拽）在 M3 有明确可执行的复测手段，B 的未测风险（IME 候选框）在 M3 前没有任何缓解手段。但本裁决 **没有照此给分**，只记录在此。

## 结论

**在本机可观测的「单帧开销与节拍」维度上，两条通路处于同一量级**：

- 报关节拍（p50）**不可区分**（Δ/N=0.32，且该统计量无分辨力）
- 尾部抖动（p95/p99）**B 略窄**，但仅 1.45~3.07 倍噪声，属弱信号
- 掉拍率（dropRate）**A 略低**，2.04 倍噪声，同为弱信号

**这个结果不能支撑"选 A"或"选 B"的排他结论**，它支撑的是一个更具体的判断：**两条通路的性能差异远小于本机的测量噪声带，因此选型不应由性能决定，而应由 D1（层间对齐）能否测出、以及 blocked 的两条（异 DPI 跨屏与 IME）在 M3 真机上的风险可缓解程度决定。**

`conditional` 的原因是 **D3（10 分钟 × 3 轮长稳）未执行**——PRD §1.4 M2-b 明确 60s 轮跑不出泄漏趋势、长稳也不是性能对比样本，两者不互相顶替，故 D3 的 20 分不计。

**D1 已补测完成。** 原量 Δpx/Δframe 判 `blocked(capability)`，理由是**参数不恒定**（22 份普查里自然态 20 拒 / 1 无检出力 / 0 齐性，唯一齐性是人造注入轮 `lag60`）——这不是"来不及"或"样本不够"，加大 n 救不了。转向 `coupleRatio`（层间独立性）后拿到**判据级证据**：A-I 五轮 `0.010101~0.015152` 对 A-NC 两轮 `1.010101 / 1.020202`，分离度 `66.67` 倍。

**DEFECT-1 的根因不是"阈值定得太高"**：注入占空比 = `12/150 = 8%`，**中位数按定义不会被 8% 的样本移动** ⇒ 该判据在任何机器上都几乎不可能触发。而 `P95` 落在最上面 5%，`8% > 5%` 正好落进受影响集合 —— 这是由占空比与百分位定义的算术关系，与机器无关。

**DEFECT-4 是教训 #34「规则写在注释里、不写进代码分支 = 没写」的又一实例**：文件里「0.000~0.050 才算 INDEPENDENT」这句要求，在代码里**没有任何分支承接**，只能靠"数据恰好落在那儿"满足。

### G.5 环境敏感性（**T04 结论的成立前提，必须写明**）

`coupleRatio` 对环境负载极度敏感。同一二进制、同一臂、同样 60s：

| 环境 | 另一窗掉拍 | `coupleRatio` | `dropRate` |
|---|---|---|---|
| 安静（22:53~23:00） | 4 / 5 / 6 | `0.010127 / 0.012626 / 0.015152` | `0.000404 / 0.000505 / 0.000404` |
| 高负载（01:20~01:51） | 138 / 176 / 125 | `0.349367 / 0.446701 / 0.316456` | `0.013933` |

**`138/4 = 34.5` 倍**与 **`0.013933/0.000404 = 34.5` 倍** —— 两个量同倍数放大，说明**不是判据变了，是环境基线变了**。

故 G.2 那批数据标注 `environment="quiet", capturedAt="2026-11-21T22:53~23:00"`。**任何复跑都必须先跑一次 A-N 短轮做环境前置门**（`win0/win1 dropRate > 0.002` ⇒ `ENV_NOT_QUIET`，abort、不产出任何 `coupleRatio`）。高负载下 A-I 会落进 `[0.05,0.50)` 中间带 —— 按 §2.4 状态转移表第 3 行判 `UNMEASURABLE`（**判据不可判，不判 A 差**），这也是 DEFECT-4 修复后才有的正确行为。

**⚠ 连带事实：G.3 的修复验证轮（v5/v6）也在高负载环境采的。** 未注入窗 `dropRate` 为 `0.009598 / 0.011553`（并行）与 `0.059072 / 0.062153`（串行），是安静基线的 **19~154 倍**。这不影响修复结论——两个修复都是**方向判别**（`CROSS_P95_RATIO` 串行 `3.60~3.65` vs 并行 `0.9989~1.0039`；`DRIFT_FRAMES` 串行 `0.0041` 距 1.0 上界 244 倍、并行 `303.2886` 距 5.0 下界 60.7 倍）——但**那些绝对值不可与安静轮直接比较**。
