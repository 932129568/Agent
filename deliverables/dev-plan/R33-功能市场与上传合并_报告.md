## 1. 删除会话复活：根因与修复

### 根因（不是渲染问题，是双端存储口径）

- `~/.glm-chat/sessions.json` 是 Python 版遗留历史源（19 KB）。
- Electron 宿主每次启动都跑 `bootstrapLegacyImport()`，以 `mode:'merge'` 把 **DB 里没有的 id** 从该文件重新 `create`。
- 而 `server/src/services/provider.js::sessionPurge` 只删 DB / 工作区 / 计划 / 检查点，**不删 sessions.json，也不留墓碑** → 删除后重启，legacy 导入把会话原地复活。
- 前端虽有 `glm_deleted_ids` localStorage 墓碑，但它只在前端合并时生效，server 端导入看不见。

### 修复（三层，两端共用）

| 层 | 文件 | 改动 |
|---|---|---|
| 服务端墓碑 | `server/src/services/session-migrate.js` | 新增 `DELETED_IDS_FILE = deleted_session_ids.json`、`readDeletedIds()`、`rememberDeletedId()`；`importLegacySessions` 支持 `skipIds`；`bootstrapLegacyImport` 传入墓碑 |
| 真删入口 | `server/src/services/provider.js` | `sessionPurge` 删 DB 之前先写墓碑 |
| 全量回写 | `server/src/services/sessions.js` | `saveSessions` 过滤墓碑，防删除前发出的滞后全量数组写回 |
| Python 端 | `backend/domains/settings/config_service.py` | `sessionPurge` 写同一份墓碑（两端共用 `~/.glm-chat`），封住交叉场景 |

`config.json` 零污染，`js_api` 契约零变更（`backend/api.py` 未动）。

> **已存在的复活会话**：墓碑只阻止未来复活，不会自动移除当前列表里的条目。请在新版本里**再删一次**（此时会写墓碑），之后重启即不再出现。

## 2. 上传：一个「上传文件」，所有格式

### 发现的关键事实

项目里其实有**两套加号**：R32 新增的 `composerPlusBtn` + `hubMenu`，以及 `chat/composer.js` 在运行时动态插入的 `plusBtn` + `atPop` 四项分类菜单（截图 2 就是它）。本轮把它们收敛为**一个 + 按钮、一套菜单**：

- `PLUS_ITEMS` 从 4 项改为单项 **「上传文件」**；
- `ipPlusToggle()` 统一走 R32 的 `hubToggleMenu()`；R32 菜单首项文案同步改为「上传文件」；
- R32 的 `composerPlusBtn` 保留 DOM（契约）但 `hidden`，由 `composer.js` 的 `plusBtn` 作为唯一可见入口；
- `unifiedFileInput` **移除 accept**：任意文件都能选；
- `hubFileKind()` 不再拒绝任何格式：图片/视频/文本/zip/gz/tar 照旧解析，其余（`.ppt/.pptx/.pdf/.docx/.mp3/.rar/.exe` …）统一作为 `type:'file'` 附件，携带文件名/大小/MIME；
- `send.js` 把通用文件附件的元信息以 `[附件文件]` 注入本次请求上下文，模型知道有哪些文件，不会静默丢弃；
- 原有大小限制、zip 白名单、NUL 二进制检测、200 MB 解压上限全部保留。

`.md` 走文本解析（能读全文），`.ppt` 等二进制只带元信息（前端无解析库、不新增 js_api）。

## 5. 启用制（本轮核心语义变化）

- 启用态存 `localStorage['harbor_hub_enabled']`，结构 `{experts:[], teams:[], skills:[], connectors:[]}`；**不写 config.json、不新增 js_api**。
- 默认**全部未启用**。加号菜单的 专家 / 技能 / 连接器 子面板为空时显示「去功能市场启用 →」，点击直达市场。
- 在市场中点「启用」→ 该条目立即出现在对应子面板；点选后仍走 R32 的真实指令注入链路（系统提示 + 开场提问 + chip）。
- 「停用」会同时清掉仍引用它的会话选择，指令立即停止注入；「我的功能」可只看已启用；「全部停用」一键清空。
- 未启用项即便知道 id 也无法被 `hubPick` 选中（防御式校验）。
