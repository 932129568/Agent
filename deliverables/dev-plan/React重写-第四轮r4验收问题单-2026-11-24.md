## 三、新问题：Suite E 超时（r4 新增的用例）

### 现象

```
TimeoutError: page.waitForSelector: Timeout 8000ms exceeded
  waiting for locator('.lc-chamber[data-phase="done"]') to be visible
  at tests/e2e-r3-regression.mjs:593
```

整个套件在这里抛未捕获异常，**后续用例与汇总都没跑**（所以本次没有 14/14 的总结行）。

### 已排除

| 猜测 | 排除依据 |
|---|---|
| 选择器写错 / phase 取值变了 | `LivingChamber.jsx:137` 仍是 `data-phase={phase}`；`143/160` 里 `'done'` 仍是合法分支 |
| 发送按钮没点到 | 上一行 `click('.chat-send-btn')` 未报错，超时点在**等待 done 态**而不是点击 |

### 头号嫌疑（未实证，按可能性排序）

1. **端点未复位**：Suite C 把 Base URL 改成 `https://api.anthropic.com/v1` 并保存；
   Suite E 直接发消息，没有把它切回测试桩。
   而测试桩只接管**后端 API**（`addInitScript` 注入 `HARBOR_API_BASE` + `HarborDesktop.apiBase`），
   **不接管模型端点** ⇒ 聊天请求打到真实 anthropic，没有流回来 ⇒ 永远进不了 `done`。
2. **`promptCache.js` 在桩环境抛错**：r4 新增该模块并改了 `agentEngine`；若它在桩返回的
   响应体上取字段失败，run 会中断在流式之前，同样到不了 `done`。

### 最省事的区分实验（未做）

把 Suite C 里改 Base URL 的那一行注释掉再跑：
- **E 立刻通过** ⇒ 坐实"端点未复位"，属**测试用例顺序缺陷**（脚本自身问题，不是产品缺陷）；
- **E 仍超时** ⇒ 转查 `promptCache.js`，看它在桩响应上的取值路径。
