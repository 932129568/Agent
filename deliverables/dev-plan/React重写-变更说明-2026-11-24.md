## 一、产品代码修复（7 条，会改变运行行为）

### 1. 应用根本无法编译：跨行单引号字符串（r19，最严重）

| 项 | 内容 |
|---|---|
| 现象 | `node build.mjs` 直接失败：`Unterminated string literal`；单测 39/40/41/43 也红 |
| 根因 | `src/services/workflowEngine.js:446` 起，用**单引号**包了一个跨 4 行的字符串（JS 非法）。单引号串不能含真实换行 |
| 改动 | 改为模板字符串（反引号），`{{input}}` / `{{upstream}}` 占位符逐字保留（`workflowEngine.js:447-453`） |
| 验证 | 构建 OK（708,051B）；**单测从 47 里 4 红 → 47/47** |

> 那 4 条单测红**不是逻辑问题**，是模块 import 就失败。只看“单测红”去查逻辑会白查。

### 2. 应用一渲染就崩：`activeModel` 在声明前被使用（r13）

| 项 | 内容 |
|---|---|
| 现象 | 窗口空白，e2e 连 `.hb-shell` 都等不到（10s 超时） |
| 根因 | `src/shell/AppShell.jsx` 里 `topSubStatus` 的两个分支（原 148/149 行）引用 `activeModel`，而 `const activeModel` 声明在其后（原 152 行）⇒ **TDZ**，渲染即抛 `ReferenceError: Cannot access 'activeModel' before initialization` |
| 改动 | 声明前移到首次使用之前（现任：`AppShell.jsx:162`） |
| 验证 | `shell=true`（修复前 false）；e2e 全绿 |

### 3. 僵尸子代理：取消发生在 runner 启动前时会永久挂起（r14）

| 项 | 内容 |
|---|---|
| 现象 | `subagent.js purgeSubagents` 用例断言 `aborted===true` 失败 |
| 根因 | `spawnIsolatedSubagent` 把 runner 放进 `Promise.resolve().then(...)`。若此时已被 purge，runner 仍会被调用并拿到**已 aborted** 的 signal；若 runner 只监听 `'abort'` 事件，该事件不再触发 ⇒ 任务永久挂起，而记录已被删除，**无人能再停它** |
| 改动 | 启动 runner 前判 `if (controller.signal.aborted) return 'stopped'`（`subagent.js:57`） |
| 验证 | 单测 47/47；「启动前取消」与「在途取消」两条路径分开覆盖 |

### 4. 沙箱内点「提交」毫无反馈（r18）

| 项 | 内容 |
|---|---|
| 现象 | 画布 iframe 里点表单按钮，什么都不发生，也无提示 |
| 根因 | iframe 是 `sandbox="allow-scripts"`（**不含 `allow-forms`**）⇒ 浏览器在提交**之前**就拦掉，`submit` 事件根本不触发，守卫脚本无从通知 |
| 改动 | 在**点击阶段**识别 `button` / `input[type=submit]` / `input[type=image]`（含所属 form），`preventDefault()` 并 `notify('form_blocked', action)`（`services/artifacts.js:22-24`） |
| 验证 | e2e Suite M 通过，**且原测试一行未改** |

### 5. 工具意图判定过宽：纯搜索被判成全栈研发（r11）

| 项 | 内容 |
|---|---|
| 现象 | `predictToolProfile('上网搜索一下最新的 React 19 发布说明')` 返回 `coding_web`，期望 `web` |
| 根因 | `wantsCodeOrFile` 把 `react` / `js` / `ui` / `设计` / `组件` 这类**裸技术名词**也算代码意图；该句又命中 `wantsWeb` ⇒ 升级为 `coding_web`，把文件与命令工具一并塞进工具面 —— 与该模块「裁掉无用工具省 Token」的目标相反 |
| 改动 | 联网意图存在时，必须同时出现**代码动作动词**（写/做/创建/生成/修改/重构/修复/运行/测试/构建/打包/实现/搭建）才升级 `coding_web`（`services/toolRouter.js:184` 起） |
| 验证 | 5 个分支用例全过（笑话→chat、钟摆网页→coding、搜索 React→**web**、查文档→coding_web、你好→coding） |

### 6. 兜底会静默缩减班组（r10，已被 r12 的等价实现取代）

| 项 | 内容 |
|---|---|
| 现象 | 模型输出不可用时，班组从 4 人缩到 2 人，界面无提示 |
| 根因 | `parseModeratorPlan` 兜底用**空意图**调 `routeGroupMembers('')`，等于按空条件筛人，`m_ui`（无 capabilities）与 `m_qa` 被静默剔除 |
| 改动 | 兜底改为保留全员 + 按 `workflowStageRank` 排序（r12 用自身实现达成同样结果，行为已复验：4/4 且按阶段排序） |
| 验证 | 直接跑 `parseModeratorPlan('bad json', roster)` ⇒ `架构师→ui设计→实现工程师→代码审查员` |

### 7. 被动 toast 吃掉了点击（v3.5/r3 期间）

| 项 | 内容 |
|---|---|
| 现象 | 群聊右下一条 info toast 盖住「■ 中止」按钮，Playwright 报 pointer events 被拦截；**真实用户那一刻也点不到中止** |
| 根因 | 容器 `.ov-toasts` 是 `pointer-events:none`，但每条 `.ov-toast` 又设成 `auto`，而 toast 内容只是纯文本，无任何可点元素 |
| 改动 | `.ov-toast { pointer-events: none }`（`shell/OverlayRoot.css`） |
| 验证 | Suite A 四条解锁全过 |

## 二、测试/判据修复（5 条，不改产品行为）

| # | 用例 | 问题性质 | 改动 |

## 五、给交付方的三条建议

1. **打包前必须跑 `node build.mjs`**。r19 连编译都没过就交付了 —— 说明交付侧没有“构建通过”这道检查。建议进 CI 必过步骤。
2. **静态铁律兜不住语法与运行期**。`iron-laws` 只扫写法（正则），r13 的 TDZ 与 r19 的语法错误它都是 PASS。
   真正兜住的是 **build + e2e（等 `.hb-shell` + 走一遍主流程）**。
3. **判据别写死清单**。本项目已出现 5 次同类问题（见第二节）。建议统一为：结构标记 + 关系约束（“两次一致”“严格非降序”），而不是具体字符串/数组。
