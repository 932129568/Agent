# R101-UX 判据与负控设计

> 生成时间：2026-11-23　｜　实现：`tools/uiaudit/assert_motion.py`（A1–A5）、
> `tools/uiaudit/assert_dead_controls.py`（A6–A9）、`tools/uiaudit/assert_motion_negative.py`（M1–M9）
> 本文按**脚本实际实现**反向整理，不是设计初稿。凡与脚本不符，以脚本为准。

## 一、三条纪律（先读这三条，否则会写出假绿）

1. **判据绿了 ≠ 机制存在。**
   本轮实测：A6 的第一版钩子只罩 `[data-amb]`（极光层，早已 `display:none`），
   门禁全绿，但 idle 状态下真正在跑的 infinite 动画是 **0 条** ⇒ 那条钩子一次都没暂停过。
   修法是把作用域放到全元素，并用「注入元素 → 切 hidden → 断言 running→paused→running」证伪。

2. **每条判据必须配反例（负控），且反例要能真红。**
   本项目的负控是**注入式**：改一处代码 → 跑判据 → 断言输出子串逐字匹配 → 还原。
   只判「红了」不判「红在哪」是不够的——变异打在错的地方，看着是 RED 其实没验到主判据。

3. **注释不是安全区。**
   `contract_diff` 的 onclick 正则、A7 死控件扫描、A6 循环计数正则都会把注释里的示例当成真实内容。
   实测代价：注释里写一句 `animation: x infinite` 就能把循环计数从 26 变成 27；写一句
   `onclick="foo()"` 就凭空多一个契约条目。

## 二、A1–A9（静态判据）

| ID | 断言 | 为什么需要（失败形态） | 现状 |
|---|---|---|---|
| **A1** | `animation` / `animation-name` 引用的每个名字，必须有同名 `@keyframes` | **死引用在浏览器里完全静默**：`animationName` 照样返回值、无 console 报错、`getAnimations()` 为空。本轮实测确认 | 0 |
| **A2** | 同一 `@keyframes` 名不得定义 >1 次 | 后者覆盖前者，通常意味着两处意图冲突 | 0 |
| **A3** | `@keyframes` 内属性 ⊆ 合成器直通白名单；布局属性单独点名 | 布局属性每帧重排，直接破「合成器直通」纪律 | 0 |
| **A4** | 不得出现 `transition:all` / `transition-property:all` | `all` 把未预期属性一起过渡，触发意外重排 | 0 |
| **A5a** | 每份 CSS 的**裸时长计数** > 基线 ⇒ 新增债务 ⇒ **FAIL**（required） | 令牌是单一事实源；裸数字让 fx-off 降级与全局改时长全部失效 | 0 |
| **A5b** | 裸时长计数 < 基线 ⇒ 已偿还，**只提示不自动降基线** | 基线要人手下调（`tools/uiaudit/a5_baseline.json`），否则棘轮会自欺 | 62（存量） |
| **A6** | 必须有「窗口隐藏时暂停循环动画」的机制（CSS `animation-play-state:paused` 或 JS） | 见 §一-1：有规则无效果是本轮实际踩过的坑 | 0 |
| **A7** | 模板里不得有「永久 disabled 且无解释」的死控件 | 用户点不动又不知道原因 | 0 |
| **A8** | JS 动态生成的 disabled 按钮必须有说明，且不得自陈不可用 | 只扫模板会漏 JS 生成路径（`planEditBtn` 就是这么漏的） | 0 |
| **A9** | 主界面不得有调试残余特征串 | 交付面残留 DEV 面板/调试 id | 0 |

### A5 为什么要拆成 A5a / A5b

原 A5 是「动画时长必须用令牌」。但存量有 62 条裸时长（`legacy.css` 是大头），
一次性清零会逼着人做大范围观感改动，风险远大于收益。
所以拆成：**A5a 是门**（新增债务一律拦，required），**A5b 是账**（存量只减不增，不阻塞）。
这样「不欠新债」是硬的，「还旧债」是渐进的。

### A7 与 A8 为什么要分开

同一个病两个入口：模板里写死的 disabled、JS 里生成的 disabled。
只扫模板时，`planEditBtn`（JS 生成）完全看不见 —— 这是**方法缺口**，不是代码洁癖。
A8 又分两条子判据：A8-a 无 `title` ⇒ 违例（用户不知道为什么不能点）；
A8-b `title` 自陈不可用 ⇒ 违例（把"不能点"当解释，等于没解释）。

## 三、M1–M9（注入式负控）

每条都是**单点变异**、机械可复现、跑完立刻还原。脚本输出 `MOTION_NEGATIVE: PASS (10/10)`
= 9 条变异 + 1 条「还原后全绿」核对。

| ID | 变异点 | 期望输出子串 |
|---|---|---|
| M1 | 追加 `.zz-probe{animation:v4NoSuchKey 1s}` | `[A1] 死引用: v4NoSuchKey` |
| M2 | 再追加一份 `@keyframes v4MaskIn` | `[A2] 重复定义: v4MaskIn x3` |
| M3 | 追加 `@keyframes zzBad{from{left:0}to{left:10px}}` | `[A3] 违例: zzBad 含 left` |
| M4 | 追加 `.zz-probe{transition:all .2s}` | `[A4] 违例: transition all` |
| M5 | 追加 `.zz-probe{animation:v4MaskIn 137ms}` | `[A5] 违例: 裸时长 137ms` |
| M6 | 删掉 motion.js 的静置暂停登记行 | `[A6] 缺失: 静置暂停钩子` |
| M7 | 模板追加 `<button disabled>假按钮</button>` | `[A7] 假按钮: 1` |
| M8 | `card.js` 追加无 title 的 disabled 按钮 | `[A8] 假按钮(JS 生成): 无 title 说明` |
| M9 | 模板追加 `<div id="dbgPanel">DEV</div>` | `[A9] 调试残余: dbgPanel` |

**纪律**：每条变异只动一个点；负控结果（RED 的原始输出）必须写进报告，
不能只写「9 条全红」。

## 四、门禁接入状态

| 判据 | 接入方式 | required |
|---|---|---|
| A1–A5a | `ui-audit-motion`（`assert_motion.py`） | ✅ True |
| A6–A9 | `ui-audit-controls`（`assert_dead_controls.py`） | ✅ True |
| M1–M9 | **不进门禁** | — |
| APCA 正文对比度 | `ui-audit-apca`（`tools/audit-apca-r101.mjs`） | ❌ False（optional） |

**为什么 M1–M9 不进门禁**：它自己要改文件再还原、耗时约 40s，还可能与其他进程抢文件。
它证明的是「判据会咬」，属于开发期验证；每轮门禁都跑一遍会把「门禁时间」和「环境偶发」捆在一起。

**为什么 APCA 是 optional**（Q10 口径）：新门禁一律先 `required=False` + 豁免登记，
翻 `True` 必须满足「曾红 → 修绿 → 判据常数未改」。APCA 从未红过——它是度量，不是回归守卫。
且它失败时必须**出现在 failed 列表里**让人看见，但不阻塞整体门禁：
一旦阻塞，有人会为了过门禁去调阈值，而阈值（正文 |Lc| ≥ 75）是设计契约。

## 五、已知盲区（写下来免得被当成"覆盖完整"）

1. **正则只取属性里第一个函数名**。`onclick="switchPanel('x');foo()"` 只算 `switchPanel`，
   `foo` 不进契约集。这与 `contract_diff` 的口径一致，但意味着「第二个调用」不受保护。
2. **A12 只扫 `.rail-btn`**。若将来出现新的按钮族（如 `.rail-pill`），可达性判据不会覆盖。
3. **集合判定判不出「还有没有人能到达它」**。实测：删掉 Rail 的会话钮后 `#panelSessions` 不可达，
   但 id 与 4 个 `setSessionFilter` 字面量都在 ⇒ 两道门全绿、功能已丢。
   ⇒ `relocate` 是三条件：保 id、保 onclick 字面量、**新宿主仍可达**；第三条无门禁可自动保证。
4. **静默失败类判据只能靠运行时探针**（死引用、`getAnimations()` 为空、Promise 永不 settle）。
   静态门禁的价值在于「便宜地拦常见错」，不在于「代替运行时验证」。
