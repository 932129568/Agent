## 0. 结论先行

用户要求「不限数量的群聊与普通单聊并行、不设任何上限/开关/配置、固化为全局默认、互不干扰」，并要求「历史会话记录页面优化」。

**根因不是缺功能，而是三处硬编码的「单活跃」假设**：

| # | 单活跃假设 | 位置 | 后果 |
|---|---|---|---|
| 1 | `RunRegistry.start()` 无条件 `this.cancel()` 取消前一个 run | `run-registry.js:5`（改前） | **并发上限实际=1**；跨会话并行会互相掐断 |
| 2 | `RunRegistry.current()` 只返回「最近启动的 run」 | `run-registry.js:20`（改前） | 切回后台会话时停止键/流式条错乱 |
| 3 | run 结束无条件 `isStreaming=false`；多处用全局标志做跨会话守卫 | `run-controller.js:1181`、`send.js`、`search.js`、`markdown.js`、`compact-command.js`、`planning/card.js`、`controller.js` | A 会话结束会清掉 B 的流式态；A 生成中阻塞 B 的发送/搜索/撤回/压缩/批准 |
| 4 | 群聊 `groupSpeak._busySid` / `_pausedSid` 单值；`groupAbort` 模块级单例 | `group.js:762/370/1053`（改前） | 第二个群启动覆盖第一个群的忙闲标记；暂停 A 群会 abort B 群的在途请求 |

**已全部消除**，且不引入任何开关、配置项或数量上限。

## 1. 实现（用户要求逐条对应）

| 用户要求 | 实现 | 证据 |
|---|---|---|
| 不限数量群聊与单聊并行 | `RunRegistry` 改为 `Map<sessionId, run>` 多槽；`start()` 只取消**同会话**旧 run | vm 真实调用：3 会话同时 start 全部存活；**20 会话**批量 start 全存活（`scale_all_alive`） |
| 不设群聊数量/并发会话数/类型组合上限 | 无 `MAX_*` / 信号量 / 队列 / 池；`Set` 与 `Map` 无容量参数 | 静态断言：4 个核心模块 grep 上述关键词 = 0 |
| 不提供开关/手动入口/配置项 | 无新增 checkbox/button/config 字段；`parallel` 由会话身份自动判定 | 模板 grep `parallelToggle` / `maxParallel` / `并发开关` = 0 |
| 不依赖用户操作 | 逻辑落在 run 启动/状态派生路径，无需任何交互 | — |
| 固化为全局默认，新建+已有会话自动生效 | 与 session 生命周期无关：会话首次运行即走同一路径；已有会话无迁移需求 | 会话结构零改动（无新增字段） |
| 群聊与单聊互不干扰 | ① 群聊 run 纳入统一注册表并标记 `kind:'group'`；② `syncAgentRunUiForSession` 遇 group 直接返回（不接管单聊发送键）；③ 群聊 busy/paused 改 `Set`；④ `groupAbort` 按会话 Map；⑤ 流式标志按会话派生 | vm 真实调用：暂停 g1 不中断 g2；`isSessionStreaming('b')=false`；群聊与单聊 run 并存 |

### 1.1 关键接口语义（RunRegistry）

| 方法 | 语义 |
|---|---|
| `start(session)` | 同会话已有在途 run → 取消旧的（S20 双发保护）；**跨会话一律保留** |
| `current(sid?)` | 传 sid = 该会话的 run；不传 = 当前可见会话的 run；该会话无 run 返回 `null`（**不回落他方**） |
| `has(sid)` | 该会话是否有在途 run（历史页「进行中」/群聊 run 均可见） |
| `all()` / `getActiveRuns()` | 全部在途快照，含 `kind: 'chat' \| 'group'` |
| `cancel(target?)` | 精确取消指定 run / 会话；默认当前可见会话，**不波及他方** |
| `finish(run)` | 只注销自己；不误删同会话的后来者 |

### 1.2 流式状态按会话派生

- 新增 `isSessionStreaming(sid?)`：指定会话是否有在途 run。
- 新增 `refreshStreamingFlag()`：按**可见会话**重算 `AppState.isStreaming`，作为多 run 下唯一正确的写入口。
- run 的 `finally` 改为重算而非无条件置 `false`。
- 7 处跨会话误用改为按会话判定：发送/续写/重生成、搜索跳转、撤回、压缩恢复/执行、计划批准、新对话继续、删除会话。
- `send.js` 增加防御式包装 `_sendSessionBusy` / `_sendRefreshStreaming`：生产环境走精确判定，单文件 harness 缺符号时按 `run.sessionId` 比对再回落全局——**同会话双发保护与跨会话并行在两种环境都成立**。
- 保存节流：由「可见会话在流式」改为「**任意会话**有在途 run 即快速保存」，避免后台并行输出丢失。

### 1.3 群聊多实例

- `GROUP_BUSY_SIDS` / `GROUP_PAUSED_SIDS`（`Set`）：任意数量群聊的忙闲/暂停互不覆盖。
- `groupAbortController/Renew/Release(sid)`：每群独立 `AbortController`；暂停只 abort 本群。
- `groupToggleRelay(sidArg?)`：支持精确暂停指定群（后台群也能停）。
- `harborStopRun(sid)`：遇 `kind==='group'` 转走群聊暂停通道。

## 2. 历史会话页重构（Before → After）

**Before**：`panelSessions` 只有「会话」标题 + 新建按钮 + 一个裸列表（与侧栏同一紧凑渲染，无信息层级）。

**After**：

| 区块 | 内容 |
|---|---|
| 概览统计 | 全部会话 / 单聊 / 群聊 / **进行中**（实时读 `RunRegistry.has`，支持多个同时进行） |
| 类型筛选 | 全部 / 单聊 / 群聊 / 进行中（`seg` 分段控件，带 `aria-selected`） |
| 搜索 | 标题 + **最近 40 条消息内容**模糊匹配；`Esc` 清空；空结果有专门空态 |
| 会话卡片 | 类型徽章（群聊高亮）· 标题 · 两行消息预览 · 消息数 · 群成员数 · 项目名/路径 · 时间 · **进行中脉冲标记** · 导出/删除操作（常显） |
| 空态 | 图标 + 具体原因（无会话 / 无群聊 / 无单聊 / 无进行中 / 无匹配）+ 引导文案 |
| 交互 | 复用既有 `switchSession` / 导出 / 删除绑定；当前会话高亮；卡片可键盘 `Enter/Space` 打开 |

**范围纪律**：`#sessionList` / `#panelSessions` / `session-item` / `session-acts` / `session-exp` / `session-del` / `session-title` / `session-time` 等既有契约项全部保留；侧栏 `#sidebarHistory` 仍用原紧凑列表，不受影响。样式写入既有 `features/chat.css`，**未新增样式文件**（保持 14）。
