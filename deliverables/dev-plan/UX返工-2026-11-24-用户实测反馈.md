### 图 1 · 请求失败的真因

界面上是「请求失败」，右侧原样抛出：

```
Failed to execute 'fetch' on 'Window': Failed to read the 'headers' property
from 'RequestInit': String contains non ISO-8859-1 code point.
```

**这不是网络问题**。浏览器的 `Headers` 只接受 Latin-1，API Key 里混进中文/全角字符时，
`fetch` 在**发出去之前**就抛这个 TypeError。原来的代码把原生报错直接甩给用户，
看起来像"接口挂了"，实际是"Key 打错了"。

## 二、已修（含验证方式）

### 1. API Key 非 ASCII（图 1）

- **改法**：在 `_modelTransportStreamInner` 发请求前逐个字符检查 `charCodeAt(i) > 255`，
  命中就抛结构化错误：`API Key 含非法字符「中」（第 4 个，非 ASCII）。请到「设置 → 模型连接」重新粘贴…`
  `compact-command.js` 的 Authorization 拼接处同样做净化。
- **验证**：用 `sk-中key` 调 `modelTransportStream` —— 现在返回上面那句人话，
  **不再出现 ISO-8859-1 原生报错**。
- 注意：我第一次把这个校验插到了 `providers/request.js` 里错误的函数（第 70 行附近，
  那个函数根本不在请求路径上），复现时仍是原生报错；移到 `_modelTransportStreamInner` 才对。
  **判据必须是"复现原错误 → 确认变成人话"，不是"代码里有这段"。**

### 2. 透色语义（图 3/4/5 的背景）

用户原话：**「我要求透色背景，不是透色桌面」**。

- **根因**：Electron 把桌面壁纸镜像成 `#lw-ambient-wallpaper` 铺在最底层
  （`electron/main.js` 的 `attachWallpaperToWindow()`），而应用自身底色是 `transparent`
  ⇒ 整个应用看起来"透到桌面"。**不是窗口透明**（`BrowserWindow` 没有开 `transparent`）。
- **改法**：① 壁纸镜像层 `display:none`；② `html/body/.app/.main` 底色改实色 `var(--bg)`；
  ③ **保留**内部卡片/侧栏的 `--surface-2`/`--card-bg` 层间透色。
- **验证**：`body` 计算色 = `rgb(240,238,230)`（alpha 1），壁纸层 `display:none`，
  `.main` 同样实色。
- **保留的口径**：`透色` = 界面内部层与层之间的半透明；`透桌面` = 不允许。

### 3. 等待态（图 2）

- 去掉圆环与三红点（`::before/::after` 与 `.s2-dots` 全部 `display:none`）。
- 改为**一条 2px 单向流动光带**（`s2WaitSweep`），运行期插入 `.s2-wait-bar`，不改模板 id。
- `fx-off` 下光带停住、只留静态淡色。

### 4. 撞击光效（图 3 的斜线）

- 硬边线性渐变 → **径向柔光晕**（`radial-gradient` + `blur(1px)`），
  四个方向各有 `--kin-origin`（0%/50%/100%），不再出现"斜条"。
