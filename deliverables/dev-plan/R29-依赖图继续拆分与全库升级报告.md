## 3. 依赖图与逐函数契约差分（用户指令①）

### 3.1 `tools/function_graph.py`
- 解析 111 个模块的顶层声明（function / class / const / let / var），按「声明行 → 下一声明行」切段；
- 依赖边 = 定义块代码（剥除注释与字符串字面量）里出现的其它顶层符号；
- **Tarjan SCC**：14 个循环簇 / 98 个循环符号；
- CLI：`--build` / `--query NAME --direction in|out|both --depth N` / `--cycles` / `--module PATH`；
- 产物：`deliverables/dev-plan/r29-function-graph.json`（111 模块 / 1154 符号 / 2743 边）。

**点名函数查询结果**：
- `connectApplyPresetNow`：12 依赖 / 2 调用方（`connectApplyPreset`、`connectLoadFromConfig`），**不在 SCC 循环簇**；
- `connectScheduleIdentify`：8 依赖 / 1 调用方（`connectInit`），**不在 SCC 循环簇**；
- 二者依赖同文件中后段函数 → 结论：**不适合抽为前置模块，应留在原模块或按拓扑闭包整体搬移**；本轮采用「可前置闭包」算法避开它们，未强行拆高耦合函数。

### 3.2 可前置闭包算法
```
earlier = 目标模块之前所有模块的 provides 并集
重复：把 deps ⊆ (earlier ∪ 已选) 的符号加入闭包，直至不动点
```
结果：`connection.js` 26、`controller.js` 29、`run-controller.js` 10 个符号可**严格单向**前置（无反向依赖）。这是拆分不破坏 `build.js` lint 的根本保证。

### 3.3 逐函数契约差分
`contract_diff.py` 第 6 类：`function_defs` = 1154 个符号 → 定义体归一化 sha256（去纯注释行/空行）。R29 拆分后与 r29 基线对比：**65 项符号归属迁移全部列为允许，逐函数哈希零变化**，即「代码零改写、仅重新编排归属」。
