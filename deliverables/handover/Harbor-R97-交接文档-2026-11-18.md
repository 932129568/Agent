## 0. 先读这段（TL;DR）

Harbor 是一个**本地优先的桌面 AI 客户端**：Electron 主进程 + Node 服务层 + 单个 3.6MB 的 `harbor.html`（前端全部逻辑内联在一个文件里）。数据全部留在本机 `%USERPROFILE%\.glm-chat\`，不上云、不联网同步。

当前可交付状态：**全部门禁绿、可安装可运行、两处实机 UI 缺陷已修**。但有一个 **P0 级数据一致性问题未修**（消息截断不更新 `updatedAt`，重开会话可能回退失效），详见 §7.1。

**接手第一天请按此顺序做**：

| 步骤 | 动作 | 验收标准 |
|---|---|---|
| 1 | 读 §1 定位与 §2 架构 | 知道三层各自的职责边界 |
| 2 | 跑 §6.1 的门禁命令 | 13/13 PASS、pytest 506 passed |
| 3 | 双击 `D:\harbor\Harbor.exe` 冒烟 | 窗口起来、能发一条消息 |
| 4 | 读 §7.1 的 P0 | 判断是否先修它（建议先修） |
| 5 | 需要改 UI 前读 §5.3 | 否则一改 `frontend/src` 就打红契约门 |

**源码在哪**：本文档不内联源码（全量 447 文件 / 91,125 行，且 `harbor.html` 是 3.6MB 构建产物）。逐文件清单见附件 **`source-inventory-2026-11-18.md`**，主文档 §4 给目录职责与关键文件索引。

## 2. 架构总览

### 2.1 三层结构

```
┌─────────────────────────────────────────────────────────────┐
│ Electron 主进程  electron/main.js (589)                     │
│  · 窗口/协议 harbor://app/harbor.html（privileged scheme）    │
│  · userData 重定向到 CONFIG_DIR/electron-profile             │
│  · 单实例锁、优雅停机、导航外链拦截                           │
├─────────────────────────────────────────────────────────────┤
│ preload  electron/preload.js (86)  →  window.harbor 桥       │
├─────────────────────────────────────────────────────────────┤
│ Node 服务层  server/src/ (46 文件 / 11,460 行)               │
│  · registry.js  js_api 方法注册表（51 公开 / 117 隐身）       │
│  · services/*   业务实现（guard/sessions/experts/mcp/…）      │
│  · SQLite（libsql）+ 文件双源持久化                          │
├─────────────────────────────────────────────────────────────┤
│ 前端单文件  harbor.html（构建产物，禁手改）                    │
│  ← frontend/src (117) + frontend/styles (14) + React 岛       │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 关键数据流

1. **一次提问**：`composer.js` 取输入 → `chat/send.js` 建消息 → `agent/run-controller.js`（1364 行，Agent 主循环）→ `providers/request.js` 发 HTTP → `agent/sse-parser.js` 解析流 → 逐 token 追加 DOM → `sessions/store.js` 持久化。
2. **工具调用**：模型返回 `tool_calls` → `agent/tool-executor.js` → `window.harbor.invoke('<method>')` → preload → Node `registry.js` → `services/guard.js` 三档护栏裁决（always/session/off）→ 实际执行 → 结果回填上下文。
3. **会话恢复**：`sessions/store.js` 双源合并（后端 SQLite + 本地 localStorage），**按 `updatedAt` 取新、平局取后端**——P0 问题就出在这个规则上（§7.1）。

### 2.3 构建链（三段，全部幂等）

```bash
# ① React 岛：模板/组件 → iife
npm run build:island          # = cd frontend/react && node build.mjs
# ② 前端拼接：117 src + 14 css + 2 prebuilt → harbor.html（含压缩）
npm run build                 # = node frontend/build.js
# ③ 一步到位（①+②）
npm run build:all
```

- 输入清单是**唯一事实源** `frontend/manifest.json`（styles 顺序 + prebuilt + scripts 顺序）。
- 压缩默认开；`--no-minify` 或 `HARBOR_NO_MINIFY=1` 关闭（排障用，实测省 11.92%）。
- **`generated/*.jsx` 与 `harbor.html` 禁手改**——前者由 `frontend/react/tools/html-to-jsx.mjs` 从模板生成，后者是构建产物。改可见结构只改 `frontend/index.template.html` 的 `<template id="harbor-legacy-fallback">`。

### 2.4 运行环境与覆盖口

| 变量 | 作用 | 备注 |
|---|---|---|
| `HARBOR_CONFIG_DIR` | 同时重定向**数据目录**与 **Electron profile** | `electron/main.js:233/272`，QA 隔离测试的标准手段 |
| `HARBOR_LEGACY_FILE_PROTOCOL=1` | 从 `harbor://` 回退到 `loadFile` | 排障用 |
| `HARBOR_NO_MINIFY=1` | 构建关压缩 | 见上 |

> **自动化启动 exe 的坑**：从带 `ELECTRON_RUN_AS_NODE=1` / `NODE_OPTIONS` 的 shell 拉起 `Harbor.exe`，exe 会退化成纯 Node 解释器，秒退 exit 0、无日志无 profile。启动前必须 `delete env.ELECTRON_RUN_AS_NODE; delete env.NODE_OPTIONS`。**用户双击不受影响**。

## 3. 功能说明

前置提醒：`README.md` 与 `AGENTS.md` 顶部都有 **R70 退役声明**——Python 契约层已删，文中"pywebview / Python 桌面壳 / backend 实现"段落是历史原文。**当前唯一运行链是 Node/Electron**。

### 3.1 对话核心（`chat/` `providers/` `agent/`）

| 能力 | 实现位置 | 要点 |
|---|---|---|
| 流式对话 | `agent/run-controller.js` + `sse-parser.js` | 逐 token 追加；思考过程单独展示；usage 明细（输入/输出/缓存命中/费用） |
| 思考深度 | `settings/connection*.js` | off/min/low/medium/high/max 六档 |
| 多模态附件 | `chat/attachments.js` | 图片/视频/文本；实际能力取决于端点 |
| 自定义端点 | `providers/provider.js` `hybrid.js` | OpenAI 兼容，自动剥离 DeepSeek 专属字段 |
| 智能档路由 | `agent/router.js` | 按问题复杂度自动选模型/思考档 |
| 预算硬停 | `agent/budget.js` `analytics/cost.js` | 会话级单调计数器，耗尽即停发新请求（在跑的工具跑完） |
| 熔断 | `agent/guard.js` | 同工具同参数 ×3 无进展 / 15 步无进展自动停 |
| 上下文压缩 | `agent/compaction.js` `context.js` | 阈值 = 模型窗口 × 档位比例（0.4/0.6/0.8） |

### 3.2 Agent 工具链与护栏（`agent/tool-executor.js` `server/src/services/guard.js`）

内置工具：`read_file` / `write_file` / `edit_file`（行号制）/ `list_dir` / `search_files` / `run_command`（白名单 + 写操作去重）/ `screenshot` / `clipboard_read` / `clipboard_write` / `kill_process`（pid 权威反查 + 关键进程保护名单）/ `open_path` / `pick_path`。

**三档护栏矩阵**：`always`（每次确认）/ `session`（会话信任态）/ `off`（全放行），配套 confirm-token 一次性令牌防重放。护栏裁决在 Node 侧二次 enforce，不信任前端。

### 3.3 群聊协作（`group/`，Beta）

- 群主配置 N 个模型成员（各自模型 + 身份），指定主持人，成员**独立上下文**。
- 接力机制：只注入「群主任务原文 + 指名给自己的消息 + 交接给自己的文档 + 自己的历史（尾部截断）」，绝不注入其他成员中间产出全文。
- 交接零解析依赖：模型按约定输出【交接文档】小节；解析失败也无损——上一条消息全文即交接。
- 相关：`group/files.js`（群文件）、`group/mention.js`（@ 指名）、`group/endpoints.js`。
- ⚠ 这里是 P0 数据问题的现场（§7.1），也是操作条不对称的现场（§7.2）。

### 3.4 专家中心与功能市场（`expert/` `shell/hub-market.js`）

- 专家中心：浏览包 → 选中 → 执行（`expert/center.js` `orchestrator.js` `package-store.js`）。
- 功能市场：顶栏 tab + 搜索 + 我的功能；分区热门卡片；专家/专家团切换；**只有在这里点「启用」的条目才出现在会话页「+」菜单**；启用态存 localStorage（独立 key，不碰 `config.json`、不新增 js_api）。

### 3.5 MCP（`integrations/mcp-panel.js` `server/src/services/mcp.js`）

- Streamable HTTP + stdio 双传输，协议钉 `2025-06-18`。
- 连接池 keep-alive，空闲 60s 回收，错误连接不污染池；stdio 温启（启用即预热）。
- 工具三档注解推导（readOnly→session / 无注解→always）+ 后端二次 enforce + 全量审计。
- 凭证 DPAPI 字段级加密（`mcp_servers.json`，Claude 配置兼容）。
- 已知边界：仅实现 tools，**resources/prompts 未接入**。

### 3.6 本地模型（`settings/local-model.js` `server/src/services/local-proxy.js`）

- 五预设探测：Ollama / LM Studio / vLLM / llama.cpp / LocalAI（四端口并行，≤1s）。
- 元数据四级来源：内置精确表 → `/api/tags` 服务器声明 → 前缀启发式 → 保守默认。
- 工具能力降级：400 特征错误自动去 tools 重发；`tool_capable=off` 不发 tools。
- 慢推理适配：首字节等待态、120s 停滞 watchdog、max_tokens 默认 4096。
- 本地模式零费计费 + MCP 确认框追加幻觉风险提示。

### 3.7 生成式 UI（`generative/`）

模型可产**只读组件描述**（非 HTML/JS），由前端按白名单渲染：
`Table` / `Card` / `KeyValue` / `Timeline` / `BarChart` / `TextBlock` / `EmptyState` / `Skeleton` / `StatTile` / `Progress` / `Checklist` / `Chips`（`registry.js` 实测注册 12 个）。

- 零动作执行：描述符里不含可执行动作，`safeParse` 严格模式拒未知字段。
- 数据引用走 `data-ref.js` 投影，`projection.js` 负责修订号与 XSS 边界。
- ⚠ 注释与测试名仍写 "eight components"，与实际 12 个不一致（§7.4）。

### 3.8 记忆与检索（`settings/memory.js` `search/` `server/src/services/memory.js`）

### 7.1 🔴 P0 — 消息截断不更新 `updatedAt`（数据一致性）

**症状**：群聊里用「回退 / 重新生成 / 编辑重发」截断历史后，重开会话（或切走再切回）可能发现截断**没生效**，旧的长版本又回来了；反向场景下也可能出现短版本覆盖长版本。

if (!prev || (s.updatedAt || 0) > (prev.updatedAt || 0)) byId.set(s.id, s);
...
put(backend); put(local);   // 同 id 时取 updatedAt 较新的一侧（平局=后端完整版）

## 8. 判据工程教训（给下一轮做验收的人）

这些是踩出来的，不是抄的。**每一条都对应一次真实的假通过或误判**。

1. **断言恒真是最大假通过源**：祖先 `display:none` 不改子元素 `getComputedStyle().display`。用 `checkVisibility()` + `getClientRects().length` 交叉校验；无副作用类判据必须配**负控**。
2. **"看得见" ≠ "点得着"**：fixed 覆盖层下元素仍"可见"。要 `elementFromPoint(中心)===自己` 或真实 `page.click`。R96 就是只验了几何没验可点，装出去的包按钮点不动。
3. **层叠上下文会让 z-index 白写**：`#chatContainer > * {position:relative; z-index:1}` 让每条消息自成上下文，子元素 z-index 出不了父级。要抬就抬 `.message` 自身。
4. **换键必须换全**：动态化字段要全库扫描，否则 `undefined`→空串，判据丢维度仍 PASS。**复合选择器要一起搜**——R96 漏了 `.message.assistant .content .msg-actions`（特异性 0,4,0，现为 `legacy.css:605-609` 的墓碑注释），它压过 `chat.css` 的 0,3,0，导致新声明成死代码，且两条挂载路径宽度差 2.1px。
5. **容差取自被测对象自身 = 恒真**：块级元素自动宽恒等于容器宽减 margin。容差必须钉契约常量或用外部基线。
6. **`textContent` 无视 `display:none`**：判"文字让位"必须逐节点 `checkVisibility + rects`，且要剥离装饰元素（把 `.msg-time` 算进正文造成 2.7px 假遮挡）。
7. **`max(0, x)` 会毁掉判据信息**：余量被夹成恒 0，看不出"只剩 0.7px"很紧。要用带符号量。
8. **夹具选偏导致系统性低估**：补测"下一条被盖面积"得 0px²，因为夹具里下一条是右对齐短气泡、x 区间不交集。换左对齐长消息才量到 1938px²。
9. **负控也会恒真**：往"下一条消息"注 `z-index:99` 时比值纹丝不动（按钮有 57.7% 露在盒外，z-index 再高也盖不到）。
10. **产物元数据不能当回读校验**：asar header 的 `integrity.hash` 是打包时算的。必须自己按格式定位回读算 hash（`qa/r90/verify-asar.mjs`）。
11. **静态花括号扫描会把 `@media` 嵌套和注释算错**：某条规则生不生效只能看 `getComputedStyle`。
12. **验证者要能撤自己的结论**：R97 里 QA 撤 3 条、工程师撤 3 条，才从"两个都可能有理"收敛到真实缺陷。只信一方会误伤或漏判。
13. **改默认行为时"计数/纯量"断言会集体变红且藏在远处**（R91 漏了「渲染 id 数=300」）。检索口径是"任何以默认态为基准的绝对值"。
14. **备份还原校验必须在工程根跑**，否则校验的是备份副本自己，自证恒 OK。
